## 本次最小兼容修订

该 Qwen3 文件的模板 SHA-256 是 `5595e8741bb5500f9d395e05a0aefe6ca1e8d54c5dd8b98bcf7760d895fdc6e6`。旧 M4 仅接受另一份已知 Qwen3 模板，因此在 `chat` 构造提示时明确拒绝这份文件；普通分词已经可用。

本修订仅增加这份模板的精确身份，沿用已支持的非思考、无工具文本模式。新旧模板的不同是：

1. `startswith` / `endswith` 改为长度相同的首尾切片比较；字符串短于末尾标记时，起点取零。这与原比较等价。
2. `split` 的首个、末个元素索引改为 `first` / `last` 过滤器。`split` 结果始终非空，因此等价。
3. 相应控制语句仍使用去除左侧空白的标记；用户消息输出和非思考生成前缀未改变。

这份比较限于当前支持的字符串、非思考、无工具文本语义。没有增加任意 Jinja 执行，也没有宣称支持模板的工具调用或思考分支。合成测试检查新旧模板的首轮/续轮 token 一致、中文与边界输入、混合权重跨进程续聊；未知模板及改动后的模板继续拒绝。

计算内核、权重解码器、三个 Parser、公共 ABI、采样算法及主实验参数均保持 M4 字节身份。另补充指定模型的预检与验收入口，绑定模型身份、架构、词表大小和实际权重消费路径；新模型快照也必须属于指定文件。

独立解包验证还覆盖 Windows 深层目录：元数据预检向小型 C 检查程序传入扩展文件路径；原生启动器为长路径可执行文件显式指定应用程序路径，工作目录仍选用较短的已有父目录。这两处是验收工具的路径修复，不改变模型计算。

## 固定实验

使用 INT8、F64 两套构建，各自保持单线程。新增混合权重在两套构建中均要求报告 `gguf_block_dequant_ordered_f64`，不把该路径称为 W8A8。每套构建内部做一致性检查，不要求两种数值构建的输出逐字节相同。

| 阶段 | 用例数 | 内容 |
|---|---:|---|
| 元数据预检 | 12 次调用 | 2 新模型 × 2 构建 × 普通分词/首轮模板/续轮模板；不绑定、不推理 |
| 原 Q8 回归 | 8 项 | 2 旧模型 × 2 构建 × 贪心/固定种子；贪心还对照 M2 封存输出 |
| 新模型前向 | 4 项 | 2 新模型 × 2 构建；token ID 1–8，context 容量 8，检查完整有限 logits、上下文边界、reset/prefill 末行重放和第二进程的全部 8 行重放 |
| 新模型续聊 | 8 项 | 2 新模型 × 2 构建 × 贪心/固定种子；两轮对话、跨进程恢复、reset 重放 |

每项续聊启动 `whole`、`first`、`resume`、`reset` 四个进程，每项前向启动两个进程。正式阶段共 72 次原生调用，另有元数据预检；这不是吞吐基准。新格式逐块反量化路径的耗时未经实机测量，不预报运行时长或加速幅度。

对话 context 容量固定为 512，每轮最多生成 32 token。两轮消息固定为：

```text
Reply with only the word blue.
刚才说的颜色是什么？ Reply with one word.
```

| 参数 | 贪心 | 固定种子 |
|---|---:|---:|
| temperature | 0 | 0.7 |
| top_k | 0 | 40 |
| top_p | 1 | 0.9 |
| repeat_penalty | 1 | 1.1 |
| repeat_last_n | 0 | 64 |
| seed | 20261107 | 20261107 |

参数直接沿用 [M4 协议](../validation/m4/protocol.json)。生成达到回复上限会按 `reply-limit` 记录，允许保留 token 截断时的原始 UTF-8 字节；上下文溢出、不完整事件或异常退出不通过。不以必须回答 `blue` 作为数值正确性的替代标准，回复原文随证据保留供人工检查。

## 必须满足的验收条件

- 所有阶段完整，进程正常退出；预检记录、源码、程序、模型与协议身份一致。
- 前向完整 logits 全部有限；同一构建内的进程重放一致，reset/prefill 末行与原末行一致。
- 连续两轮与退出后恢复的回复、有效 KV、logits、token 历史、配置、随机数状态逐字节一致。
- reset 后首轮重放一致；原 V1 的累计生成诊断计数保留累计语义，单独比较；不能影响另一会话快照。
- 原 Q8 的四项贪心用例复现 M2 已接受记录；新模型架构、词表大小、权重路径和快照模型身份匹配指定值。
- 不跳过新模型聊天，不删坏样本、不拼接中断结果；缺失或改动的预检/输出记录阻止通过。
- REVIEW / FULL 归档内容均与已写出的证据逐项一致。

成功状态为 `M4_SELECTED_MODELS_FUNCTIONAL_PASS`，并在结果内记录 `selected_experiment: M4-P1-SELECTED`。它证明这两份指定模型在上述短上下文、固定用例下的加载、执行与存盘续聊功能。它不等于独立真实模型数值参考、模型质量、长上下文能力或性能验收；原合成数值对照仍作为另一层证据保留。

## 运行

包目录为独立的 `C:/Projects/MICIUS-M4-P1`，模型保留在 `C:/Projects/MICIUS/models`。在 Git Bash 执行：

```bash
cd /c/Projects/MICIUS
bash ../MICIUS-M4-P1/scripts/run_m4_selected.sh all
```

入口先核对四个模型身份，再从源码构建、运行合成测试和外部模块检查，随后完成新模型词表/模板预检，最后开始正式推理。每次创建新的 `results/m4-日期-时间-随机号`，结果 ZIP 位于本包 `exports/`。预检或推理失败保留证据，修复原因后重新 `all`，不复用半完成结果。需要更换模型目录时设置 `MICIUS_MODELS`。

仅构建/合成验证可执行 `bash scripts/run_m4.sh prepare`。在包内用 `bash scripts/run_m4_selected.sh preflight <准备目录绝对路径>` 可仅检查真实文件的分词和模板，不运行模型；此步骤会保存预检证据，随后正式实验使用 `all` 另建目录。

本包不修改核心 MICIUS 目录、模型、旧 M4 包或任何 Git 状态。交付构建与元数据预检的实际完成状态见包外核验记录；正式新模型结果已由用户运行并审计，详见发布说明；重新运行会产生独立的新记录。
