# I3 · 两层 FFN 的精度干预

**保留 W8A8 主策略。** token 42／1 的首步同时回切 layer 3 和 31 的 FFN，logits 相对 L2 从 19.84%／15.26% 降至 6.74%／5.27%。

末层 gate/up 对两次输入的作用较大，单独回切 down 仍会消费上游误差。单步 L2、KL 与真实目标的 NLL 衡量不同问题，下一项实验转为连续文本评分。

### I3 干预与观测契约

来源 `MICIUS-INT8-I25-P1/micius/docs/INT8_I3_INTERVENTIONS.md`。

#### 输入与范围

父包为 I2-R1，SHA-256 `07978094ed9526e56e63f53bc4b72d41d25da56e1778ab14ff41c25f2a53c5f4`。I2 发现本组样本的量化、整数消费及输出符合 I1 契约；layer 3 的 SwiGLU 尖峰和 layer 31 的残差抵消值得进一步干预。I3 复用该结论，检查指定消费精度改变后的因果响应，不重复 I2 全矩阵点积审计，也不把旧验证计入新测试。

固定 token 42、1 的第一步。层号从零开始。每个策略在自己的轨迹上执行：输入不会被原 F64 轨迹的张量替换。跨策略对照相同的模型、token、初始状态和非 GEMV 运算。变化可能从第一个选中的 GEMV 继续传播；后续的“相对 F64 误差”并不是同输入局部误差。

| 策略 | 改为 F64 的消费 | 32 层模型中的次数 |
| --- | --- | ---: |
| NONE | 无 | 0 |
| L3_GU | layer 3 gate、up | 2 |
| L3_DOWN | layer 3 down | 1 |
| L3_FFN | layer 3 gate、up、down | 3 |
| L31_GU | layer 31 gate、up | 2 |
| L31_DOWN | layer 31 down | 1 |
| L31_FFN | layer 31 gate、up、down | 3 |
| L3_L31_FFN | 两层 gate、up、down | 6 |
| F64_ALL | 所有 GEMV，含 QKV、O 和 LM | 161 |

本表和指标均在首次目标运行之前固定；没有按结果新增策略。32 层合成模型只用于覆盖相同的路由结构。它不提供自然语言质量证据。

#### 实现

仅 CMake 和 `AICoreEngine.cpp` 在父包的既有文件中需要改变。新增私有 `I3Intervention.h/.cpp`、专项测试、运行器和分析器。公共头文件、ABI、preset、I1 量化与整数消费实现、冻结的 `ReferenceGEMVAVX2.cpp` 及 frozen oracle 均保持原件内容。

私有编译开关 `MICIUS_I3_INTERVENTION` 默认为 OFF。未启用时，I3 实现文件从编译列表排除。启用时要求 I1 AVX2 严格配置与 row-pair，并禁止同时启用 I2；I1 原来的 fast-math、PW2、compact scales、D1、ITT 等限制继续生效。

选中 GEMV 调用原 `PrepareF64GEMVInput`，用此次调用独有的 double scratch 保存 F32 的精确转换，然后调用未修改的 prepared-F64 row-pair 消费。经过 V1 验证的权重描述符仍走原预验证入口，其他调用走原校验入口。原始 Q8 权重和 scale 没有变为 F32 权重，也没有把中间激活持久化为 double。

未选中 GEMV 保留 I1 的准备与消费。FFN 原有 W8A8 共享准备仍执行；即使两个消费者均回切，也保留这一步，使该实验只干预消费结果。F64 scratch 不与 I1 共享 scratch 重叠，gate/up 的原 W8A8 视图不会被 F64 准备覆盖。诊断开销未优化。

#### 输入快照与记录

每个 GEMV 包装在准备之前（共享准备的 gate/up 除外）保存 F32 输入，并在消费结束后逐字节核对。另为 FFN 保存**共享准备前**的 `ffn_input_before_prepare`，在 gate 和 up 均完成后核对，并把该快照与两次消费输入分别比对。这个新增检查覆盖共享准备至两次消费的整个区间的前后状态，补齐 I2 只覆盖消费阶段的范围；它不声称能检测先写入再恢复的瞬时修改。

`records.jsonl` 的 schema 为 1；配对 `tensors.f32` 为小端 F32 连续载荷。begin 记录 token、position、层数、策略和 MXCSR；每次 GEMV 记录实际选择、输入输出形状与偏移、输入不变标记和前后浮点控制。另记录 embedding、attention residual、共享准备前的 FFN 输入和各层最终 residual。LM 的输入就是 final norm 输出，LM 输出就是完整 logits。

只允许 RNE、FTZ/DAZ 关闭等约定控制位（MXCSR mask `0xffc0` 为 `0x1f80`）；sticky 状态位可以不同。观测方法保护并恢复 MXCSR，不引入新的数值计算。完成记录要求每层五次 GEMV、每层一次 FFN 输入核对及最后一次 LM，且无悬空调用。失败不生成成功 completion；运行器不会接受不完整证据。

#### 验证与指标

专项 C++ 测试以独立保留的 frozen oracle 检查 36 种形状、校验与预校验两种入口的输出位模式，包括尾块、奇数行、较大维度、符号权重、零值及动态范围变化；检查输出哨兵、输入不变、路由集合和失败状态。合成及目标运行各自检查：

- 原 v0.6 BASE 与 F64_ALL 的完整 logits 字节相等。
- I3 OFF I1、I3 ON 无环境变量、I3 NONE 的完整 logits 字节相等。
- 同一策略在第一个选中 GEMV 的输出之前，所有已观测张量（含该 GEMV 输入）与 NONE 逐字节相等。
- 实际 F64 调用数、输入快照、完整观测顺序、有限性、偏移和 completion 一致；记录的 LM 输出与运行时 logits 文件逐字节相等。
- 对指定完整 I2 结果 ZIP 的历史控制轨迹检查另行记录，不替代新运行的验证。

主指标是完整 logits 相对 L2、RMSE 和 `KL(F64 || candidate)`。相对 L2 为 `||candidate-reference||₂ / ||reference||₂`；改善百分比为 `100 × (1 - 本策略相对 L2 / NONE 相对 L2)`，负数表示变差。top-1 及 token 2 的概率仅作描述。逐边界相对 L2 都比较各自轨迹；不能把不同阶段的 RMSE 相加成误差归因。

down 输入峰值能量占比为最大绝对值分量的平方除以输入平方和。残差抵消比为 `(||attention_residual||₂ + ||down_output||₂) / ||layer_output||₂`。二者用于描述当前轨迹的敏感性，不构成对所有输入的证明。

#### 证据边界

本单元是固定两枚 token、首步、单一 GGUF 的有限干预。相对 F64 靠近不等于自然语言质量合格；单个策略对一个 token 变好、另一个变差也必须如实报告。最终候选需要匹配 tokenizer、固定自然文本及 teacher forcing 的 NLL/困惑度，再决定精度/效率取舍。诊断进程的耗时不代表部署速度，GEMV 回切次数也不等于耗时占比。

原 I2 的 644 次矩阵检查和 45,219,840 个块点积位置属于历史 I2；本轮新记录只是干预路由与张量的观测，不能写成同等规模的整数算术复审。没有新增全运行时 sanitizer 结论或稳定集成授权。

### I3 结果：layer 3／31 FFN 的受控精度干预

来源 `MICIUS-INT8-I25-P1/micius/docs/INT8_I3_RESULTS_2026-10-11.md`。

**本工作单元完成。指定样本中，layer 31 gate/up 的激活量化对最终偏差具有显著影响；仅回切 down 的收益较小。两层 FFN 一起回切能把两个首步的 logits 相对 L2 降低约 66%／65%，但仍不足以认定质量合格。**

本轮完成新编译、专项测试和目标模型运行。父包为复查通过的 I2-R1；本轮是有意更改指定 GEMV 数值算法的实验，不是修复违反 I1 契约的实现。稳定 v0.6、父包和历史结果均未被替换。

#### 实验身份与设计

- 完整运行目录：`results/i3-20261011-113400-tx79p7w6`。
- 状态：`TARGET_INTERVENTIONS_COMPLETE_REQUIRES_REVIEW`。
- 目标 GGUF：`smollm2-360m-instruct-q8_0.gguf`，386,404,992 字节，SHA-256 `48ab3034d0dd401fbc721eb1df3217902fee7dab9078992d66431f09b7750201`。
- 父源码 ZIP SHA-256：`07978094ed9526e56e63f53bc4b72d41d25da56e1778ab14ff41c25f2a53c5f4`。
- 完整结果 ZIP：44,065,689 字节，288 个成员，SHA-256 `4a98eb4b786b96698daf854a9e79b4cc42398418d265331d45056cc14b22fe2a`。交付名为 `MICIUS-INT8-I3-RESULTS-2026-10-11.zip`，内容与运行器生成的 ZIP 相同。

Windows x64 Clang64；沿用接受的 preset，strict FP、O3、native、ThinLTO，CPU 4，构建并行度 4。原始 BASE 源码目录的完整 119 文件集合及散列在构建前后均一致。目标为 32 层、hidden 960、FFN 2560、词表 49,152。

token 42、1 各自从新上下文的 position 0 开始，只执行一步，warmup 为 0。层号从零开始。九个策略及主指标在运行前写入 `I3-EXPERIMENT-PROTOCOL.json`；执行后没有扩充策略。选中算子在**当前轨迹自己的输入**上消费 F64，未用 F64 基线激活覆盖候选激活。F64_ALL 是全消费回切的验证对照，不是混合候选。

#### 完整 logits 结果

相对 L2 以原始 F64 为分母；下表百分数越小表示全向量越接近 F64。KL 为 `KL(F64 || candidate)`，不是自然文本 NLL。

| 策略 | F64 GEMV 次数 | token 42 相对 L2 | token 1 相对 L2 | token 42 KL | token 1 KL |
| --- | ---: | ---: | ---: | ---: | ---: |
| NONE（I1） | 0 | 19.839264% | 15.263988% | 0.232341 | 0.266851 |
| L3_GU | 2 | 19.642714% | 15.228428% | 0.237487 | 0.234574 |
| L3_DOWN | 1 | 19.364212% | 13.742759% | 0.222286 | 0.145993 |
| L3_FFN | 3 | 19.651005% | 11.252328% | 0.237195 | 0.074424 |
| L31_GU | 2 | 6.302734% | 8.950780% | 0.044819 | 0.254338 |
| L31_DOWN | 1 | 19.426234% | 13.329753% | 0.203209 | 0.205717 |
| L31_FFN | 3 | 6.042500% | 9.869399% | 0.032354 | 0.264249 |
| L3_L31_FFN | 6 | 6.740175% | 5.273256% | 0.043488 | 0.078304 |
| F64_ALL | 161 | 0% | 0% | 0 | 0 |

L31_GU 相对 NONE 的 L2 降幅为 68.2310%／41.3602%；L3_L31_FFN 为 66.0261%／65.4530%。回切次数不能换算为性能成本，因为矩阵大小和不同消费路径的成本不同。

token 42 的 F64 top-1 为 216。NONE、所有仅 layer 3 回切方案和 L31_DOWN 的 top-1 为 2；L31_GU、L31_FFN、L3_L31_FFN 为 33。所有混合方案均未恢复这个首步的 F64 top-1。token 1 的全部方案 top-1 都为 2，这同样不能证明概率分布已经恢复。

#### 这次干预说明了什么

**layer 31 gate/up 是本组样本中更有效的精度干预位置。**此前 I2 观察到 layer 31 down 的输入误差及残差抵消较大，但这不意味着 down 自身是最值得先回切的消费者。新实验在完全相同的上游轨迹上回切 gate/up 后，token 42 的 SwiGLU 输出（down 输入）RMSE 从 0.607224 降至 0.251408，down 输出 RMSE 从 13.184653 降至 4.590779；layer 31 最终 residual 的 RMSE 从 12.748043 降至 4.364367。token 1 的对应 down 输入 RMSE 从 0.402853 降至 0.263753，layer 31 residual RMSE 从 12.254452 降至 6.337385。

对 L31_GU，第一处变化确实是 layer 31 gate 输出；此前 411 个观测张量（含这个 gate 的输入）与 NONE 逐字节一致。因此，这里的端到端变化可归于选定 gate/up 消费精度改变及其后续传播。它仍不能把 gate 和 up 的各自贡献分开，因为本单元将二者联合干预。

**仅回切 down 无法消除它接收的上游误差。**token 42 的 L31_DOWN 虽将 logits 相对 L2 从 19.839264% 略降至 19.426234%，layer 31 down 输出 RMSE 却由 13.184653 增至 13.349766，最终 residual RMSE 也由 12.748043 增至 12.902466。token 1 同样出现 down 输出和 residual RMSE 略增、最终 logits L2 改善的组合。这与误差方向、残差相加、后续归一化有关，不能以某一中间 RMSE 的增减替代端到端指标，也不能把不同阶段的 RMSE 相加。

**layer 3 的尖峰值得关注，但并非两个样本上最大的单点收益来源。**L3_FFN 对 token 42 的 logits L2 仅改善 0.9489%，KL 还从 0.232341 增至 0.237195；对 token 1 则改善 L2 26.2819%，KL 降至 0.074424。这种输入依赖也解释了为什么“两层都回切”不能假定优于所有单层方案：其 token 42 L2 6.740175% 高于 L31_FFN 的 6.042500%，但 token 1 更好。

**L2 和概率分布指标并不单调一致。**token 1 的 L31_GU 虽把 L2 降到 8.950780%，KL 仍为 0.254338，接近 NONE 的 0.266851。token 2 的概率从 F64 的 0.151944，变为 NONE 的 0.346675、L31_GU 的 0.397051、L31_FFN 的 0.406908。两层 FFN 回切把它降至 0.268132，仍与 F64 有距离。token 1 上 L3_FFN 的 KL 0.074424 还略低于两层方案的 0.078304，尽管其 L2 更高。不能仅凭 L2 排名选定最终质量方案。

#### 新验证与原始证据

本轮 BASE／I1／I3 的 CTest 分别为 11／12／13 项全通过。I3 专项验证包括 36 种形状 × 2 种 scale 校验入口的 frozen oracle 位一致、尾块和奇数行、输入与输出哨兵、九种选择策略，以及生命周期、错误配置和输入改写检测。基线目录守卫另有 11 项通过。

合成及目标模型各执行两枚 token，每枚含九个记录策略和三个额外控制，共 48 次成功的单步推理。目标部分有 18 份完整记录，包含 2,898 次 GEMV 路由／输入输出观测和 576 次从共享准备前到 gate/up 完成后的 FFN 输入核对，均通过。**这些是本轮的观测数量，不是再次执行 I2 的 644 次全矩阵整数算术审计。**

四组（合成／目标 × 两枚 token）均满足：

- BASE 与 F64_ALL 的完整 logits 逐字节一致。
- I3 OFF I1、I3 ON 无环境变量、I3 NONE 的完整 logits 逐字节一致。
- 干预前已观测前缀（含第一个选中算子的输入）与 NONE 逐字节一致；第一处实际变化均位于预期选中的输出。
- 各 GEMV 的实际路由和数量符合预声明策略；前后输入、共享 FFN 输入、MXCSR 控制、记录偏移、有限性及完成标记通过。

三类无效构建配置被拒绝；三类无效运行设置以非零状态退出。六类损坏记录（缺 completion、非有限张量、截断、错误后端、缺共享核对、共享快照不一致）被分析器拒绝。

本机保留的完整 I2 结果 ZIP 用于比对历史控制：四份目标控制的完整 logits 字节相等。另从历史张量检查了新 NONE/F64_ALL 的 1,676 个观测张量，全部相等；24 个首次干预且输入仍与 I1 相同的选中输出，与旧 I2 独立同输入 F64 输出逐字节相等。后者加强了干预实际消费了对应 F64 结果的证据，不等于重跑旧点积检查。

完整新结果 ZIP 的 CRC、288 个成员的集合和 287 项文件散列通过校验。从 ZIP 内原始 logits 独立重算了全部 18 个目标策略的相对 L2、RMSE、KL，与分析结果一致。69 项执行源码身份在运行前、运行后及交付前均一致。

相对父包，只修改两个既有文件：`CMakeLists.txt`、`src/AI/AICoreEngine.cpp`。其余 178 个既有文件逐字节保留；新增实现、脚本、测试、文档和证据另列清单。公共 ABI／头文件、preset、原 F64／I1 消费实现及其测试 oracle 未改变。

`docs/i3-evidence/` 保存摘要、两份完整目标分析、测试日志、运行身份、ZIP 重算核对和历史边界比对。完整结果 ZIP 还包含全部策略张量、原始 logits、编译命令、每条运行命令、日志和损坏记录测试输入。未声明新增 sanitizer、性能或自然文本质量 PASS；编译日志保留既有警告。
