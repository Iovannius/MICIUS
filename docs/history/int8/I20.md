**I20 候选正确性检查通过，局部测量有效，但性能未满足预设继续条件。停止该候选，不制作正式模型采样包；I19 保持当前研发基线。**

#### 目标与实际实现

在已接受 I19 上，仅实现三查询头共享 Value 读取、范围检查和 F32→F64 转换。固定八维×三头寄存器块、32 行时间窗口。每头概率独立，保留原 F64 FMA、沿时间累加顺序和每一步 F32 舍入。

三头 Softmax 按各头原指数和求和顺序先写私有概率工作区；Value 完整成功后才提交三头输出。失败恢复浮点环境和 errno，并从未修改的 I19 分数按原逐头路径执行。异常未屏蔽、形状不适用、短路径和范围失败均回退。最大新增 96 KiB 概率暂存，没有常驻 KV 副本；本轮未测真实模型峰值内存，不将设计上限当作实测内存增量。

原源码仅 CMake 与 AICore 私有派发改变；新增候选源、头文件和专项测试。431 个原文件保持身份，22 个共享编译单元参数一致，默认 OFF 恢复 I19；原 Value、Score、GEMV、公开 ABI 和 preset 保持身份。

#### 正确性与机制检查

- 1,176 个候选数值、边界和保护页案例通过（544 次快速路径、608 次回退比较，另有24个直接边界检查）。独立逐时间标量 FMA 参考、完整输出、失败时已写前缀、最后分数工作区、输入不变、MXCSR、x87状态、errno、舍入、FTZ/DAZ、NaN/Inf 与上界/别名检查均包含在内。
- 原 Value 的 2,035 项、原 Score 的 1,420 项及 ABI/生命周期检查通过。
- 14 次小型合成模型命令通过：三头 GQA dim64 的128/2048步，dim32和dim64两头回退，以及各配置八轮生命周期/重置。完整 logits、预测和末行输出复现接受的 I19。没有目标模型推理。
- 最终 CLI 与局部测量程序的机器码均检出实际共享：每八维、每时间步共有2次 V 扩展、6次累加器扩展、6次 F64 FMA和6次 F32收窄；热循环无调用、无栈访问，整个程序无VNNI。
- 准备期间测量程序曾缺少头文件搜索路径，补齐后构建通过；初次失败日志保留。没有候选数学修改，也没有发生性能重试。

#### 唯一一次局部筛选

协议在实现前冻结。32/128/256/2048行，dim64、三头、stride320；单缓冲和八缓冲轮换；CPU4、六对交替顺序，每计时块2,097,152个逻辑行组。每格两实现各一块预热。共48对、96个正式局部计时块，全部保留。

#### 能解释什么

本候选确实减少了重复V准备，却没有降低完整工作单元的耗时。共享同时需要更多独立累加器；为控制寄存器占用，维度块从原每头32维变成三头8维，增加了概率访问与循环调度，并引入组内准备和暂存。最终机器码未出现累加器溢出，说明失败不能简单归咎于栈溢出。

这些是可核对的实现差异，尚未单独测出各项耗时；本轮不能精确断言是哪一项抵消了共享收益。测量支持当前固定候选停止，不能推出所有三头Value实现必然更慢、整个后端达到上限，或I19的模型吞吐下降。

本轮与I18的状态不同：I18因波动超限而测量不确定；I20在预设稳定性范围内持续变慢，局部性能门槛明确未通过。无须为本候选再启动一轮真实模型实验。
