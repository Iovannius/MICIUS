# I25 · 完整模型四行重排

**v0.7 采用 P1 验收实现。** 原 I25 的 13 阶段内存解析在第一条 I22 输出后停下。P1 首轮波动超限，独立复跑相对 I22 提升 18.4635%，稳态私有提交减少约 207 MiB，生命周期峰值增加约 389.5 MiB。

原缓冲退休和失败回滚经独立契约检查。放行依据为独立复跑的 4 条完整输出、24 条计时及预设数值、波动和内存门槛。P1 修复的是验证程序，数值候选与协议沿用 I25。

### I25 实现与证据边界

来源 `MICIUS-INT8-I25/docs/I25-DESIGN.zh-CN.md`。

#### 从 I23 / I24 到完整候选

I23 完整合成工作集通过了局部成本筛选；I24 保留 I22 数值计算，测量准备、消费及额外展开成本，结论为条件预算支持继续实现。这两步均不能替代候选模型的 5% 吞吐验收。

本包逐字节复制冻结的 `PanelGEMV.h/.cpp`。四行重排按输出行组织 Q8 字节与 scale，使一次整数归约产生四行的块点积。每行保持原始块次序及 F64 乘法、累加顺序，继续采用原有激活量化。查询、Attention、KV 布局和公共 C ABI 均未修改。gate/up 共用一次量化准备和一次激活展开。

目标模型共 161 次矩阵消费、129 次输入准备/展开每 token。额外展开暂存最多 10 KiB，不持有整套额外原始权重。本轮只测这一机制，不追加不同内核或搜索实现组合。

#### 绑定事务和所有权

1. 沿用 I22 的张量与描述符验证，先构造完整的候选面板、退休清单和暂存区。
2. 全部成功后切换模型成员。分配或校验失败会丢弃新构造对象，原模型及会话保留。
3. 成功切换并重置后，清空引擎原 Q8/scale 消费指针，释放原 row-major QKV 和引擎原描述符。
4. Shell 在完成 I22 原有 public-scale 释放后，按内部退休清单校验所有原 Q8 缓冲的唯一所有者及别名范围；整个清单验证完成后才释放。F32 embedding、norm 和 GGUF 文件映射仍由原所有者持有。

退休清单保存地址身份和长度，用于校验释放，不能作为可解引用的旧权重引用。对 public C API 的调用者，不主动释放调用者提供的任何缓冲；只有 Shell 知道并释放自己的分配。构建选项 `MICIUS_I25_PANEL_GEMV` 默认关闭，关闭时恢复 I22 路径。词表行数不适合四行分组时整个模型保留 I22 路径；不采用部分绑定。

已验证的重新绑定故障注入覆盖 91 个 C++ 分配失败点，不能解释为已枚举所有操作系统故障。实际释放旧 Q8、破坏原 public 描述符后继续计算，以及重置、错误输入和反复加载均有合成检查。完整目标模型仍需用户运行时验证。

#### 内存账本

| 有效载荷类别 | I22 | I25 活跃路径 |
|---|---:|---:|
| 独立矩阵 Q8 + 引擎描述符 | 517.5 MiB | 四行面板 388.125 MiB |
| 引擎额外 row-major QKV + 描述符 | 70.3125 MiB | 绑定成功后释放 |
| 额外激活展开暂存 | 0 | 10 KiB |

上表是申请有效载荷，不是进程指标。I22 已释放的 172.5 MiB Shell public 描述符不能再次计作 I25 新收益；F32 embedding 和 KV 容量继续保留。`MODEL-LEDGER.json` 是历史加载阶段的来源账本，其中包含随后释放的对象，不代表 I22 或 I25 的稳态提交量。

构造时新旧数据暂时共存，峰值允许增加一个 388.125 MiB 面板及约 28 MiB 分配余量，因此协议采用 +416 MiB 上限；不承诺峰值随稳态等量降低。实际 after-load / after-decode PrivateUsage 应各减少至少 128 MiB。Working Set、PrivateUsage、Job PeakProcessMemoryUsed 和 VirtualQuery 区域长度分开保存与解释。

#### 证据与停止规则

准备时重建 I25 和默认关闭版本，核对全部 22 个共享编译单元与 I22 的选项，只允许新增 I25 选择宏、私有头路径和一个 PanelGEMV 编译单元。新增面板文件及其契约测试明确采用 `-fno-fast-math -ffp-contract=off`，继承冻结原型的浮点约束。基线直接使用冻结 I22 程序。三份程序的机器码均检查无 VNNI。

每个子任务保存实际退出码、命令、内存和原始输出散列，事件链记录固定顺序，结束清单绑定完整证据。独立 Decimal 算式再次计算全部配对值、区间波动和门槛。缺失、改写、额外记录或终止封存不完整时不能准入；归档必须通过完整文件集合、CRC 及逐文件 SHA-256 核验。

本包仅申请成为下一实验候选。稳定版本仍为 v0.6，已接受研发基线仍为 I22；只有真实采样和审阅之后才可能调整该状态。

### I25-P1 内存阶段校验修复

来源 `MICIUS-INT8-I25-P1/docs/I25-P1-REPAIR.zh-CN.md`。

#### 已确认的故障

原运行 `i25-20261030-132848-42969531` 在第一条 I22 完整输出检查后停止。子进程正常完成 2,048 步、退出码为 0；完整 logits、末位置 logits 和预测序列的 SHA-256 均复现冻结 I22 参考。I25 候选尚未运行，24 条正式计时均未启动。

原校验器要求 11 个内存阶段，遗漏程序一直输出的 `headers_mapped` 和 `engine_allocated`。实际记录的 13 个阶段完整且顺序正确，因此报错源于校验器。原代码还用 `records[3]` 读取清理后账本；在真实的 13 阶段记录中该位置是 `translated_before_bind`，也须一并修正。

此前合成测试只查找清理后的一条记录，没有调用正式运行的完整内存校验器；流程模拟又复用了同样错误的 11 阶段列表，因而未暴露该缺陷。文件散列一致和原有测试通过的事实并未改变，但此前由此给出可运行结论的验证覆盖不足。这是交付脚本问题，与模型计算的退出状态分开判定。

#### 本次修复与验证

- 严格要求真实的 13 个阶段，顺序、重复、缺失、额外阶段和子进程身份均须正确；不通过跳过记录或放宽顺序来修复。
- 用 `bound_after_cleanup` 名称读取账本。正式目标模型仍要求释放 180,879,360 字节 public scales，候选原 Q8 所有权退出；原有内存门槛不变。
- 三类合成模型的 I22、默认关闭和 I25 共 9 条完整内存轨迹，均调用与正式 `read_record` 相同的校验函数；小模型只传入自身几何尺寸和回退状态。
- 将此次真实 I22 内存记录完整复制为带来源散列的回归输入。原解析函数可重现故障，修复后的正式 `read_record` 可验证原子任务的封存、退出码、输出散列和完整内存记录。
- 补充缺失、重复、乱序、PID 不符、计数异常和旧权重未释放的负例。流程模拟验证内存错误在第一阶段就停止，不能进入正式计时或被判通过。

#### 交付与实验边界

本修正版目录为 `MICIUS-INT8-I25-P1`。原 I25 目录、ZIP 和失败结果原样保留，不重写其 STOPPED 状态，不从该目录拼接采样。

P1 保持原 I25 的完整数值源码、CMake、I22 程序、固定输入和 `protocol.json` 字节一致。其目的仍为 I22 / I25 的 4 条完整输出检查和 24 条正式计时，要求至少 5% 整体吞吐收益并满足原有稳定性、区间与内存约束。P1 不是新的性能候选，也不是 I25 已通过验收的证据。

使用 README 中的新目录命令从头运行。构建和合成检查由准备阶段完成；真实模型采样由用户执行。已接受研发基线继续为 I22，核心 v0.6 不改变。
