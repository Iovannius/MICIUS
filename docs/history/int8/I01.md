# I1 · W8A8 的算术契约

**建立近似参考。** 32 元素一块，标量 INT64 和 AVX2 整数消费相互核对。128 步 greedy 的四对中位吞吐收益为 63.15%，两后端已沿不同 token 历史生成。

I1 同时改变激活表示和算术分组。固定输入 32 步的 scalar/AVX2 全 logits 相同，F64 与 I1 出现明显偏差，因而需要同输入的独立参考。

### I1 W8A8 数值与工程契约

来源 `MICIUS-INT8-I25-P1/micius/docs/INT8_I1_CONTRACT.md`。

日期：2026-10-03。状态：候选，默认关闭。公共 C ABI 与模型格式保持 v0.6；I1 改变 reference 执行模式下 GEMV 的数值路径，CLI 明确输出 `approximate_w8a8_i1`。

#### 激活量化

每个至多 32 元素的输入块独立处理。将有限 F32 输入精确转换为 F64，取 M=max(abs(x))，用 binary64 的 `d=M/127` 作为 scale。M=0 时，codes 与 scale 均为 0。否则在 binary64 下计算 x/d，按 nearest-even 舍入并夹到 [-127,127]。

必须使用 round-to-nearest、masked exceptions、FTZ/DAZ off；不支持的 MXCSR 返回错误，不能静默得到另一套量化结果。sticky exception flags 不改变契约。F64 scale 避免极小 F32 输入的 scale 下溢；输入含 NaN/Inf 时准备失败，视图无效。

这是逐调用的输入快照。scratch 与输入、输出、权重不可别名；调用方保持 scratch 有效且只读直到消费者结束。view 不跨 scratch 复用、reset 或销毁留存。当前运行时同步调用，不引入缓存身份或跨 token 复用。

#### 点积与输出

原 Q8 权重 q_w∈[-128,127]；输入码 q_x∈[-127,127]。每块整数点积为 Σ(q_w*q_x)，最多 32 项，因此绝对值至多 **520,192**，INT32 足够。每块独立还原 scale，不能跨不同权重 scale 直接累加整数。

AVX2 使用 signed INT8→INT16 拓宽和 `vpmaddwd` 产生 INT32 配对和，再做无溢出的整数规约。没有采用会在中间 INT16 配对和发生饱和的字节乘加捷径。SCALAR 用逐元素 INT64 点积作为实现对照。

每块反缩放严格按以下顺序：

```text
t = double(dot) * double(weight_scale)
sum = sum + t * activation_scale
```

块按列顺序累加，关闭浮点 contraction，最后检查有限性和 F32 可表示范围后输出 F32。奇数输出行与部分末块都有独立边界路径，无超出有效权重字节的向量加载。空的合法行范围为 no-op；失败后不能把已写的部分输出当成完整结果。

F64 baseline 对每项乘法与归约的组织不同，I1 还引入 activation scale 近似。误差报告不把这些因素单独归因于某一个来源；I1 的 bitwise 验收对象是本契约下的整数 oracle。

#### 准备、信任与容量

每 context 的量化 payload 为 N+8*ceil(N/32) 字节，N=max(hidden_dim,intermediate_dim)，另有对齐和对象开销。没有新增长期权重影子。I1 构建不分配 prepared-F64 输入 scratch；FFN gate/up 使用同一量化快照。

checked 消费检查每块 scale 有限、zero_point/padding 为零。省略重复 scale 检查的入口仅由现有 V1 模型私有验证状态选择；它不接受外部声称“已经验证”的模型。失败回退保留在 W8A8 checked 消费契约内，不静默混用 F64 算法。

配置 `MICIUS_I1_BACKEND` 只接受 OFF/SCALAR/AVX2。候选要求 AVX2 与 V1 descriptor 预验证开启；fast-math、prepared-F64、compact scales、PW2、D1、ITT 组合被拒绝。F64 后端默认选择和其原数值测试不被改成 I1 的误差容忍测试。

#### 验收层次

1. 独立 quantize oracle 使用 floor/奇偶规则，逐块核对 code 与 scale；独立 INT64 数学实现核对完整输出。
2. SCALAR/AVX2 固定输入的逐步 logits 要求 bitwise 相同；自回归摘要也要求一致。
3. I1/F64 分别报告误差与输出分歧；暂不设置未经任务数据支持的通用准确率阈值。
4. 自然文本质量、长上下文、性能和准备成本单独验收。当前 32 步重复 token 仅用于初筛。

旧 F64 asymmetric GQA 数值 oracle 保留在 BASE 中，不适用于新近似算法。I1 runtime 测试复用原 ABI、绑定、reset、生命周期检查；完整量化数值由新 oracle 和双实现 trace 补充，不放宽旧 oracle 的容差。

指令语义参考：[LLVM AVX2 intrinsic 文档](https://clang.llvm.org/doxygen/avx2intrin_8h.html)、[Intel 编译器参考](https://www.intel.com/content/dam/develop/external/us/en/documents/cpp_compiler_classic.pdf)。

**十四、I1 数值偏差——本轮真正需要解释的问题**

原始轨迹每份包含 32 步、vocab 49,152 的 F32 logits。两组输入分别是重复固定 token 1 和重复固定 token 42；每组都是同输入历史对照，但不是 32 个独立自然语言样本。

| 指标 | token 1 轨迹 | token 42 轨迹 |
| --- | ---: | ---: |
| top-1 一致步数 | 32/32 | 0/32 |
| F64／I1 的逐步 top-1 IDs | 2／2 | 216／2 |
| 相对 L2 误差中位数 | 0.1477828855 | 0.1925911900 |
| 相对 L2 误差最大值 | 0.1526398833 | 0.1983926354 |
| RMSE 中位数 | 0.7873417725 | 0.8487787604 |
| 最大绝对误差的全轨迹最大值 | 3.4275374413 | 4.1699032784 |
| cosine 中位数 | 0.9946105464 | 0.9899152849 |
| 平均 KL(BASE ‖ I1)，自然对数 | 0.2376303080 | 0.2237485332 |

token 42 在第一步就由 F64 的 216 变成 I1 的 2，不需要长序列累计才出现分叉。F64 当步第一名与第二名的 logits 间距约 0.536592，不能仅凭“可能是极小 near-tie”将观察略过。

token 1 轨迹的首选 ID 虽相同，第一步原始 logits 的 softmax 下，ID 2 的概率从约 **15.1944%** 变成 **34.6675%**。token 42 第一步中，ID 216 的概率从约 14.4936% 变成 4.9086%，ID 2 从约 0.9771% 变成 9.0840%。这些是对应 logits 的分布诊断，不是自然语料准确率，也不能未查 tokenizer 元数据就把 ID 2 命名为某个特殊符号。

部分 raw-logit L2 变化包含公共偏移；但 KL、首选翻转和去均值后仍存在的误差表明，差异并非只有不改变 softmax 的统一常数平移。高 cosine 或某一组 top-1 全部一致不能替代质量验收。

这些数据说明偏差真实存在，值得优先定位；它们尚不能单独证明实现有 bug，也不足以认定整模型自然文本质量一定不可用。不要把相对 L2 的百分比称为语言能力下降百分比，更不要把重复 token 42 的 0/32 当成语料准确率为零。
