# I17 · 查询转换复用

**采用。** I17 在一次 Score64 调用内复用查询转换。相对 I15 提升 2.0742%，末段提升 2.4384%。

整体超过 2% 线 0.0742 个百分点，慢配对仍保留。现有证据支持这一步，对类似微小调度修改的未来收益没有外推保证。

### I17 范围、数值契约与证据边界

来源 `MICIUS-INT8-I17/docs/I17-DESIGN.md`。

#### 从 I16 到本轮选择

I16 已完成验收：I15 总体矩阵组占 57.834%，Attention 占 40.155%；最后 1,024 个位置 Attention 占 50.303%。在本轮插桩差额中 Attention 占总体 69.628%、末段 78.646%。自身 Score 成本为 7.432 ms/token（末段 11.675），Value 为 6.177（末段 9.337）；Score 在全部八个剖分样本中均高于 Value。

因此选择 Score64 的重复工作作为下一局部候选。不同引擎的缩放、最大值、概率归一化边界不同，不能把单项差额视作可直接回收时间。I16 的未插桩差额约 10.063 ms/token，不能沿用 I15 场次约 9.4 ms/token，也不能把消除全部差额当作本轮目标。

本轮暂停泛化剖分与新一轮 llama 计时。I17 只回答一个问题：移除 Score 八行批次中重复的查询精度转换，在保持数值和资源契约后，是否带来足够的同场端到端收益。

#### 最小改动

原 I11 Score64（由 I15 保留）按八条历史 Key 同时计算，使用两个四通道 F64 累加器；每行仍按维度 0 至 63 累加。查询在每个八行批次中重复从 F32 转换为 F64。

I17 在一次符合条件的调用开始时准备 `double prepared[64]`。后续完整八行批次改为读取和广播这些 F64 值，Key 的加载、转置、转换及累加顺序保持原样。2,048 行时，完整八行批次的查询转换由 64×256 次降为 64 次；F64 广播与 Key 转换仍然存在。四行和标量尾部继续使用原 F32 查询路径。

新增查询数组为 512 字节固定局部存储，不能据此断言整个函数栈帧只有 512 字节。没有新增堆分配、持久缓存、跨头复用、跨 token 状态或 KV 布局。

快速路径条件：64 维、行数至少 128、步幅至少 64、原有限且不小于 1 的分母契约、尺寸计算无溢出、输出与输入/最大值不重叠、全部浮点异常被屏蔽。短路径调用原 I11，原 I11 返回 UNSUPPORTED 时继续由原 AICore 回退处理。128 行阈值在真实采样前固定，没有基于目标模型结果搜索阈值。

#### 数值与异常行为

1. F32 有限查询到 F64 的转换是精确的；在相同 MXCSR 下重复转换相同输入不会改变值。DAZ、FTZ、舍入模式和已有粘滞标志保留。
2. 每个历史行仍从正零 F64 累加器开始，按相同维度顺序执行 64 个 F64 FMA；无横向归约或浮点重排。缩放后先做原有限检查，按原时间顺序写 F32 分数，最大值仍取舍入前的 F64 分数。
3. 与旧八行路径一样，先判断该批次全部点积是否有限，随后提交该批次。任何非有限点积都会恢复入口 MXCSR，并从头调用已接受的 I11 路径；I11 自身在需要时重放原四行实现。这保留首次失败位置、已写前缀及最大值，并清除较晚行带来的推测性异常标志。
4. 若有效点积有限，除以有限且不小于 1 的正分母不会溢出为无穷；因此沿用旧八行路径的 `Consume` 调用策略。F32 分数转换可能产生的舍入/溢出行为也必须与原实现一致，不新增错误规则。
5. 对未屏蔽异常不进入新路径，以保留原路径的异常顺序；输出别名也不准备新查询，以避免改变原读写行为。

编译使用原固定工具链、显式禁用 VNNI，候选 Score 单元使用 `-fno-fast-math -ffp-contract=on`，与原 Score 的有序 FMA 策略一致。全部共享编译单元除私有启用宏外保持原参数。关闭 I17 时恢复 I15 的编译单元集合和参数。

#### 验证内容

专项测试比较独立逐行标量 FMA 参考与原四行参考，检查完整分数、部分输出、保护区、F64 最大值、MXCSR 和输入不改写。覆盖 128 行门槛、8/4/1 尾部、非对齐输入、多个步幅、任意有限位模式、消去误差、符号零、次正规数、舍入模式、FTZ/DAZ、不同分母、Inf/NaN/sNaN、推测性异常标志、无效参数及保护页末端。

最终链接的 `I17Dot8x64` 维度循环须包含八个 F64 FMA、八个 Key 向量转换和四个 F64 查询广播，不能出现 F32 查询转换、VNNI 或累加器栈访问。此检查验证代码形态，不等于证明硬件全部成本。

32/64 维合成模型检查连续解码、完整输出一致性、两种模式、重置、重复加载、非法输入和资源释放。运行器模拟检查缺失/慢样本、错误退出、身份/参数/资源变动、中断保留及归档校验。真实两篇文本仍必须在用户运行时逐字节复现 I15。

#### 性能解释

开发期间只做一次固定形状的合成 Score 扫描检查：32、128、256、2,048 行，包含入口校验与准备成本，六次交替顺序。原始每次数据均保留在 `validation/SYNTHETIC-KERNEL-ONLY.json`。它只支持候选值得交付，不证明目标模型或端到端性能；短路径的波动也不作加速结论。

正式实验为四条完整输出加 24 条 I15/I17 计时，不新增剖分。2% 的总体及末段准入门槛、每篇/每区间回退限制、10% 稳定性限制及内存限制预先锁定。若差异太小或数据不稳定，就如实保留未接受/不确定状态。不会因局部成功而假定后续必然获得类似 I13 的收益。

### I17 正式结果复核 · 2026-10-21

来源 `reports/I17-review-20261021-172501-04e98710/I17-RESULTS-REVIEW.zh-CN.md`。

**结论：比较有效，I17 通过预设准入条件，可接替 I15 成为下一工作单元的实验基线。稳定产品默认不变。**

运行：`i17-20261021-172501-04e98710`。用户终端采样，助手仅复核已有证据，无目标模型推理、补采样或新对手计时。

#### 预设门槛与边界

- 总体提升2.0742%，达到2%的预设门槛；超出准入线 **0.0742个百分点**，余量较小。
- 末段提升2.4384%，达到2%的预设门槛；两篇总体均无回退，各篇各区间均通过0.98的下限。
- 全部总耗时与区间稳定性通过。最差单元为s00/I17/1024-2048，max/min=1.039037294，低于1.10。
- s00/I17/r5是较慢样本，总耗时77.6150056秒；对应同轮I15为77.6212671秒，单对收益仅约0.0081%。该样本原样保留，未删减、替换、重跑或与历史样本合并。
- 各篇中位生命周期峰值提交内存均约1593.37 MiB，I17相对I15没有增加，低于“基线×1.02＋8 MiB”的门槛。这不是物理工作集或无泄漏证明。

这是符合既定规则的小幅成功，不是新的大幅跃升，也不能由一次运行宣称稳定跨环境收益。未新增统计置信度门槛，未通过事后删样本扩大收益，亦未因准入余量较小临时提高门槛。

本轮没有llama.cpp计时，不更新当前跨引擎差距，也不把历史llama速度与本轮I17速度拼接为同场对比。

#### 当前主线状态

I17成为下一工作单元的实验基线；I15保留为历史已接受基线。稳定产品默认未变。
本轮支持“把Score64查询转换移出历史Key批次”这一局部改动带来约2%的同场端到端收益。后段收益较大，与复用机制相符；本轮无算子剖分，不能据此精确推算Score自身剩余占比或可回收时间。
后续继续围绕Score64可消除成本做局部重构，泛化采样探索保持暂停。本次未启动下一工作单元。
