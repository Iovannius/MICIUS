### I2 诊断定义与实现边界

#### 入口与生命周期

`MICIUS_I2_DIAGNOSTICS` 为默认 OFF 的私有 CMake 开关。开启后，进程环境变量 `MICIUS_I2_OUTPUT` 指定一个尚无 `records.jsonl` 的输出目录；没有该变量时不记录。只允许 position=0，运行器约束为一个新 Context 的一次 decode、warmup=0。I1 的生产配置拒绝门未被绕过。

`AICoreEngine.cpp` 在每次 GEMV 包装入口复制 F32 激活，在该调用结束后检查源输入未改变、借用准备视图与生产输出。QKV、O、down、LM 的准备在包装内执行，因此这些调用的输入未改写检查覆盖准备和消费；FFN gate/up 的共享准备在两个 GEMV 包装之前完成，因此 gate/up 的输入未改写检查各自只覆盖消费阶段，不能单独证明共享准备阶段没有改写源输入。共享准备的 codes/scales 仍会在每次消费后相对于该次包装入口捕获的输入独立核对。

2026-10-11 定点检查中，现有准备函数的源输入为只读视图，写入目标是 caller-owned codes/scales scratch；未发现写入源输入的实现。不过，这项源码观察不能替代准备前后快照的运行时证据。R1 只收紧上述表述，没有移动快照、修改 C++ 插桩或重新运行模型。

在 gate/up 两次消费之间，诊断不覆盖 Context scratch。诊断输出使用独立存储，不参与后续 forward。F64 与 I1 运行使用独立进程和 KV 状态。

`ReferenceW8A8GEMVAVX2.cpp` 只在诊断宏下把实际计算的每个 INT32 dot 写入线程局部观察缓冲，未改指令配方、块顺序或后处理。关闭宏后这些代码不参与编译。`ReferenceGEMVAVX2.cpp`、公开 ABI、原始测试容差和稳定 preset 文件均逐字节未改。

诊断计算前后恢复完整 MXCSR，包括粘滞标志。生产调用前后控制位单独核对；不静默修正生产环境。不支持的 FP 控制状态、非有限激活、错误 descriptor、输出溢出、写文件失败、同输入实现不符都导致失败，并且没有 `complete` 记录，运行器不能将其纳入成功结果。

#### 独立对照

对每次真实调用，固定原始 F32 输入、全矩阵权重与 descriptor、完整合法行范围和控制状态：

1. 独立量化参考对每 32 项计算 binary64 `max(abs(x))/127`，用 `floor`、小数部分和奇偶判定 RN-even；没有调用生产 prepare 来生成参考答案。
2. 比较实际生产准备视图、另建 scratch 的生产准备与独立 code/scale。scale 按位比较，零块、尾块与 subnormal 均受检查。
3. 使用实际准备 codes 的简单 INT64 dot，与生产调用捕获的 dot、AVX2 重放 dot、标量重放 dot 分别比较。这样错误准备不会被误标成“同 codes 下整数点积错误”。
4. 独立执行 `weighted=double(dot)*double(weight_scale); sum=sum+weighted*activation_scale`。比较两种消费与真实生产输出，隔离共享后处理和调用集成问题。
5. 对原始输入调用原样保留的 F64 prepared row-pair 入口，得到局部 F64 输出。

以上诊断文件与整数/F64 内核均使用 `-fno-fast-math -ffp-contract=off`；MSVC 路径设置 `/fp:strict`，本轮实际验证的是 Clang64。不能把这项编译边界扩大成整个 forward 无 FMA。

#### 激活近似与分组对照

独立规则重建 `xhat = double(code) * double(activation_scale)`，该乘法的结果保持 binary64。没有先将 xhat 转成 F32。

诊断数学参考逐元素计算 `(xhat*double(weight_code))*double(weight_scale)`，维持四条、每条四 lane 的 F64 累加链：块内前/后 16 项依次加入对应链；再做 `(a0+a1)+(a2+a3)`，lane 按 `(v0+v2)+(v1+v3)` 规约；尾块逐项追加。单独用原始 F32 精确提升的 binary64 输入验证该诊断树与原样 F64 入口的最终 F32 输出相同。没有改写冻结 F64 参考以适配测试。

- `same_input_f64_to_i1`：原始输入 F64 与独立 I1 完整契约的总差异。
- `input_change_fixed_f64_tree`：保持该 F64 树，改变输入为 binary64 xhat 的差异。
- `grouping_at_reconstructed_input`：重建输入的 F64 元素树与 I1 块 dot/缩放的最终 F32 差异。
- `grouping_double_max_abs`：上述最后一项在最终转 F32 之前的最大 binary64 差值。

这是明确指定浮点运算与舍入路径的分解，不是无限精度的“纯量化误差”。本轮 grouping 在最终 F32 输出上为零是测量结果，不是对所有输入的恒等式声明。

#### 局部误差与传播误差

两个后端各自形成后续输入，不能直接把它们的层输出差归罪于该层内核。对同一矩阵，设 F 为冻结 F64、I 为 I1，xB/xI 为两条路径的输入，则保存了：

```text
total_vector = I(xI) - F(xB)
incoming_vector = F(xI) - F(xB)
local_vector = I(xI) - F(xI)
total_vector = incoming_vector + local_vector
```

三者的 RMSE、max-abs、relative L2 分别报告，RMSE 不能按上述向量等式直接相加。所有 final norm / logits 对比均来自相同的 token 历史。本轮没有 greedy 分叉后的不对应输入比较。

layer 编号从 0 开始；`qkv` 是按 Q/K/V 顺序拼接的矩阵，`o`、`gate`、`up`、`down` 对应各层投影，`lm` 的 layer 字段为 num_layers。记录了 embedding、每个 GEMV 输入/输出与两种局部输出、RoPE 后 QKV、attention residual 和 layer output。

`residual_cancellation_ratio=(||R||₂+||D||₂)/||R+D||₂` 以 F64 路径的实际 attention residual、down 输出和转换后的 layer output 计算，描述该次残差相消的程度，不是统计推断或误差百分比。`down_input_peak_energy_fraction` 是最大分量平方占输入平方和的比例。

#### 文件格式与重放

- `records.jsonl`：begin、gemv、boundary、complete 记录；包含 token/position、layer/operator、rows/cols/尾块、输入输出版本、MXCSR、检查计数、首个不匹配、局部指标和小段 code/scale/dot。

因此，在本次捕获激活和矩阵上，分组差未改变最终 F32 输出；它不足以解释所见 logits 偏差。该结果不宣称所有输入的分组结果恒等。

#### 3. 偏差从哪里出现和放大

下表 layer 为从 0 开始的源码索引，layer 3 是第 4 层，layer 31 是最后一层。relative L2 的分母为对应 F64 张量范数，并非语言能力损失百分比。

首个差异为 layer 0 QKV：此前 embedding 和其 RMSNorm 后的 GEMV 输入相同。token 42 的 Q/K/V 各自 relative L2 约为 0.2689% / 0.2844% / 1.6493%。packed QKV 总体的 0.2779% 与随后 O 输入约 1.6493% 使用不同张量作为分母，不能据此认定第一步 softmax 把误差放大了六倍。

layer 3 FFN 的 SwiGLU 后激活很集中：token 42 的分量 962 为 3084.5183，占整个 down 输入平方和的 99.9892%；token 1 同一分量为 3337.2937，占比 99.9904%。token 42 在这一层的残差输出 RMSE 从上一层的 0.038568 升到 2.960794。F64 激活自身也很大，故 relative L2 并未同步增大，必须结合绝对误差看。

末层同时存在较大的 FFN 传播误差和残差相消。token 42 的 F64 attention residual / down 输出 / 相加后输出 RMS 为 626.439 / 620.609 / 48.074；范数比 `(||R||+||D||)/||R+D||` 约 25.94。token 1 相应比值约 28.52。这支持末层的敏感性判断，不是单凭相消比就证明唯一原因。

#### 7. 源码范围与下一步

I2 只改动 I1 的三个既有文件：`CMakeLists.txt`、`src/AI/AICoreEngine.cpp`、`src/AI/ReferenceW8A8GEMVAVX2.cpp`；其余修改是新增诊断源码、测试、运行/解析脚本和文档。既有 MD、history（如有）与原始证据均保留。源码差异及 SHA 清单位于 `docs/i2-evidence/`。

下一工作单元宜针对 layer 3 与 layer 31 的 FFN 精度做小范围干预，分离 gate/up 的输入误差、SwiGLU 后误差与 down 的本地量化误差，再根据连续指标选择是否建立新的数值候选。回切或量化规则修改应明确标识为算法变化。不能把本次同输入通过理解为应该直接晋升 I1。

新候选随后需要固定自然文本 token 序列的 teacher-forced NLL / perplexity，使用匹配的 tokenizer 并冻结计分协议；性能与集成验收再接续。当前 v0.6 保持稳定参考，I2 为独立诊断交付。
