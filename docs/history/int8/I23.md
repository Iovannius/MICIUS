### I23 成本筛选原型：契约与边界

来源 `MICIUS-INT8-I23/docs/DESIGN.zh-CN.md`。

当前只实现独立的四行消费原型及筛选运行器。按已授权提案，完整工作集预筛必须先达到 15% 局部耗时下降；本轮交付不提前修改模型加载器，不更改 I22 或 v0.6。把模型所有权接入放在成本预筛之后，是为避免在未经性能证据支持的路径上先做复杂生命周期改造。可行性阶段目前完成了私有所有权原型，**真实模型绑定事务尚未实现**。

#### 排列与算术

一个四行、32 列块有 128 个权重字节。四个 32 字节向量各取每行的八列；低/高半部各容纳四行的四列。激活以相同排列重复四份。

每条 `maddubs/maddwd` 产生四行各自的两个四项部分和。四组结果逐 lane 相加，再合并高/低半部，恰好覆盖原来每行的 32 个乘积，无遗漏或重复。仍使用 `abs(weight)` 与 `sign(activation,weight)`：激活范围 [-127,127]、权重 [-128,127]，两项绝对值上界 32512，不发生 I16 饱和；32 项上界 520192，不溢出 I32。

整数归约的结合顺序可以安全改变。F32 scale 保留位模式；每块仍按 I22 的 `double(dot)*double(weight_scale)`、再乘原 double 激活 scale、再加入累加器。按原块顺序累加，最后转 F32，不改成 FMA。

新布局只用于完整矩阵、行数为 4 的倍数、列数为 32 的倍数。其他形状或行切片应在未来模型调度层保留原实现。当前契约测试检查原通用路径，但没有声称已经实现了完整引擎的自动回退开关。非默认舍入、FTZ/DAZ 或异常 mask 配置会由原型明确拒绝；正常状态下比较输出及 MXCSR sticky flags、errno。没有声称对所有 x87 状态完成了验证。

#### 所有权与生命周期

`Matrix::Pack` 校验形状、长度、scale 和预算，在临时拥有者内构建；成功后交换。失败保留原对象。其复制被禁止，移动后原对象变为空；消费拒绝空对象。源权重与描述符只读，归调用者所有。成功后的重排矩阵独立拥有全部字节。测试会毒化并释放原数组，验证原型不依赖旧源。

筛选程序每个矩阵重排后只释放自己持有的原始向量，计时前检查原始数组 capacity 为零。这不是对模型加载器借用关系的变更。候选没有整套 345 MiB 常驻权重影子。打包失败和预算不足有受控检查；真实系统分配器的 OOM 异常捕获已实现，但没有人为注入实际系统 OOM。

未来若局部门槛通过，模型接入须：建立明确的私有 packed 存储所有者；绑定完整成功后，仅释放已经不被借用的源数组；保留不支持形状的旧数据和回退；证明 reset、重复加载、失败回滚及析构顺序；保持公共 ABI 和 I22 的描述符释放行为。若需扩大为广泛加载器重构，则按提案停止本候选。

#### 真实成本记账

冻结模型目录包含 225 个原 Q8 矩阵；合并 QKV 后，每次消费扫描有 161 个矩阵和 129 次输入准备。原矩阵逻辑占地为权重 345 MiB + 16 字节描述符 172.5 MiB，共 517.5 MiB；候选为 345 MiB + F32 scale 43.125 MiB，共 388.125 MiB。

候选的逻辑矩阵占地减少 25%，这不等于 DRAM 流量、缺失次数或运行时间减少 25%。新增激活逻辑加载约 258.75 MiB/次扫描。原型保留原量化输入码，再增设最大 10 KiB 展开区；因此当前实现额外 scratch 是 **10 KiB**，而不是规划时仅按替换展开码估算的 7.5 KiB。其复制和展开全部在 ROI 内。

权重生成、逐矩阵重排和分配记为 setup_seconds；预热记为 warmup_seconds；完整消费扫描记为 seconds。输出校验和落盘、进程内存查询都在 ROI 外。每个子进程独立、固定单核；所有正式筛选样本都保留，六轮交替先后顺序，不能筛掉慢样本。

计时边界没有模型的算子交错和激活传递。只说明一个代表完整矩阵工作集的局部成本是否值得继续研究。真实模型的比例 p、额外成本 h 及上下文区间影响仍待针对性观察。

#### 可证明与不可证明

静态和契约检查支持：字节排列与整数点积等价；旧数值后处理顺序保留；测试集输出、错误提交、输入只读和生命周期检查一致；最终机器码减少归约与 scale 拼装，热循环没有栈读写，未检出 VNNI。

它们不证明至少 5% 模型吞吐收益。该目标要求净时间下降至少 1/21 = 4.7619048%；完整包准入前的预算门槛仍是 p*r-h >= 5.5%。本地筛选通过也不会自动放宽或跳过这个预算。

本轮不引入 I18/I20 的失败候选，不重新搜索行数、tile 大小或量化精度，不变更 Attention，不执行泛化剖分。不根据小工作集计时预测收益。

### I22 内存分类、所有权与测量边界

来源 `MICIUS-INT8-I23/docs/I22-MEMORY-OWNERSHIP.zh-CN.md`。

以下是固定 SmolLM2-360M Q8_0、I19 接受配置的源码与 GGUF 元数据核算。它没有执行真实模型，也不是新的进程实测。精确张量目录和字节数在 `MODEL-LEDGER.json`。

| 类别 | 请求有效载荷 MiB | 所有权与生命周期 | I22 处理 |
|---|---:|---|---|
| GGUF 原件 | 文件约 368.50；张量有效载荷约 366.80 | 解析器只读文件映射，保留到卸载；F32 norm 与元数据依赖它 | 保留；不计入下列私有申请合计 |
| 解包后 Q8 权重 | 345.00 | Shell 分配，引擎借用；tied embedding 也提供输出权重 | 保留 |
| 公共 scale 描述符 | 172.50 | Shell 分配；V1 绑定读取后复制 | 只在绑定成功后释放 |
| 引擎私有 scale 描述符 | 172.50 | V1 绑定事务建立独立数组，引擎销毁时释放 | 保留 |
| F32 embedding | 180.00 | Shell 分配，解码阶段借用 | 保留 |
| Packed QKV 权重与描述符 | 46.875 +23.4375 | 引擎额外准备；原权重及私有 scale 仍保留 | 保留，不把潜在别项优化混入本轮 |
| F32 K/V cache | 640.00 | 容量 8192，32 层、KV 维度 320、K/V 两份；初始化触及容量 | 保留；2048 位置逻辑使用量为 160 MiB |
| RoPE 两张 F32 表 | 4.00 | cos/sin 各 8192×64 | 保留 |
| activation / scratch | 约 0.356 | 单步向量及 I19 四份 score 容量等 | 保留 |

以上主要私有申请合计 **1661645184 字节，约 1584.67 MiB**。早期草算约 1583 MiB 少计了一张 2 MiB 的 RoPE 表，已在交付前修正。该修正不改变 172.5 MiB 候选释放量。

合计尚不包括容器、字符串、元数据对象、分配器元数据/对齐/分页、运行库、线程栈等。不能拿它与另一次运行的 Peak Commit 相减后，把残差强行归入某一个类别。私有请求字节也不是所有时刻的 OS Commit：分配器可能保留已释放页。

GGUF 使用 `CreateFileMapping(PAGE_READONLY)` 和 `MapViewOfFile(FILE_MAP_READ)`，未发现加载器另外保存整份原始 GGUF 的私有缓冲。映射仍在并不等于映射全文件都物理驻留，也不等于同样字节数的 Private Commit。Q8 解包权重和 F32 embedding 确实是单独申请，不应被误称为“第二份原始 GGUF”。

公共描述符释放的依据是 `micius_runtime.cpp` 的 V1 绑定：先验证公共 scale，创建独立 `QuantDescriptor[]`，向内部绑定传递独立数组，并转移其所有权；原始 Q8 和 F32 指针仍借用。候选只在绑定成功之后释放公共 scale，先验证所有权集合，再从 `managed_buffers` 移除，避免卸载时重复释放。失败绑定沿用原清理流程。合成检查覆盖 tied/untied Q8 embedding、F32 embedding、不同 head 形状、重置、八轮加载/释放及非法 scale。

llama.cpp 使用冻结源码、`use_mmap=true`、CPU-only、F32 KV、ctx=8192，允许既有 repacking。其 GGUF 映射、后端重排缓冲、KV、图/工作缓冲与 MICIUS 的组织不同。本轮保留完整加载日志，观察 model load、context ready、warmup/reset、四个解码边界及释放后的进程指标；仅凭进程指标仍不能逐页证明每一类物理归属。

| 指标 | 本包字段/来源 | 可以说明什么 |
|---|---|---|
| 当前私有提交量 | `private_commit_bytes`，PSAPI `PrivateUsage` | 此阶段私有提交规模 |
| 生命周期峰值 | 阶段 `PeakPagefileUsage`；正式子进程 Job `PeakProcessMemoryUsed` | 整个加载/预热/解码生命周期的峰值，不能定位是哪一阶段的分配 |
| 当前/峰值 Working Set | `WorkingSetSize` / `PeakWorkingSetSize` | 驻留物理页面，可能包含共享/文件映射页面 |
| 虚拟映射范围 | `VirtualQuery` 的 MEM_COMMIT 按 PRIVATE/MAPPED/IMAGE 分类与 RESERVE 范围 | 地址空间范围；不代表物理驻留，也不等于 PrivateUsage |
| 请求载荷 | 源码公式和加载器逐分配 ledger | 应用申请的有效字节；不包括 malloc 额外空间和 OS 取整 |

Windows 指标定义依据：[进程计数器](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters_ex)、[Job 扩展限制及峰值](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information)、[VirtualQuery](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualquery)。复制写入的映射页仍可报告 MEM_MAPPED/MEM_IMAGE，不能直接用区域类型推导页面是否共享。

分阶段观察只在完整输出校验进程启用。观察包含同步 OS 查询和写日志，会扰动资源轨迹；不把这些进程的耗时作为正式吞吐。两引擎的 `after_load` 均代表其模型/上下文准备完成，但内部惰性准备时机不同，因此还必须看预热后与解码后。`after_release` 仍是活进程，输出向量、运行库及分配器缓存可能保留，不能据非零值判泄漏。

正式计时只比较原 I19 和 I22，继承相同输入、数学、ROI 和固定顺序。描述符释放发生在峰值可能已经出现之后，本轮不设“峰值必须下降”目标；也不把 I21 两引擎约 885 MiB 的峰值差额全部当成可回收冗余。

### 预算边界、公式与停止条件

来源 `MICIUS-INT8-I23-BUDGET/docs/BUDGET-PROTOCOL.zh-CN.md`。

本包延续 I23 原提案的“局部筛选 → 当前模型预算 → 完整候选”顺序。合成完整工作集已通过；目前只填补当前模型占比和额外准备成本的证据。源码数值内核、历史输出参考、两篇 token 输入均固定，I22 为唯一研发基线。

#### 对齐边界

当前 I22 每 token 调用 161 个矩阵，合计 361,758,720 个字节权重元素、325,632 个输出元素。输入准备 129 次，准备列数合计 175,040；消费列数合计 205,760。每层 QKV、O、gate、up、down 各一次，最后输出投影一次。gate/up 仅共享准备，不把准备重复算两次。

PROFILE 分别包围原 `PrepareW8A8Input` 和原 `GEMV_W8A8Rows`，两个计时区不嵌套。全 decode 计时用于检查计数闭合和内部时间不超过外部 ROI。最终占比的分母使用正式观察程序的外部 ROI（包含状态检查等），不是把内部 decode 时间冒充端到端时间。0–256、256–512、512–1024、1024–2048 四区间分别报告。

EXTRA 在成功准备输入后额外调用原 I23 筛选包的 `Expand`，冻结实现逐字节复制并保留原 activation scale。展开结果只作诊断，不进入模型消费。10 KiB scratch 预先触碰、只在 EXTRA 存在；无新的模型权重副本，默认关闭观察时恢复 I22 的实现。所有计数和额外操作的耗时都在外部 ROI 内，写文件在 ROI 外。

#### 固定采样与有效性

两篇输入，三程序，各四轮。轮次顺序为 I22/PROFILE/EXTRA、EXTRA/PROFILE/I22、PROFILE/I22/EXTRA、EXTRA/I22/PROFILE；不是六排列全覆盖实验。先做六条完整输出检查，再做全部 24 条计时，计时前间隔 10 秒。不能移除慢样本、选择最好轮次、提前根据预算停止、或拼接中断轮次。

检查包括真实退出码、事件链顺序、单进程串行、冻结程序/输入/协议/源码身份、输出历史散列、FP/CPU 配置、电源/休眠、原始结果完整性、逐区间计数与维度闭合。每篇、每程序、总体及每区间最大/最小时间比 ≤1.10。每篇、总体及每区间的 PROFILE/I22 配对时间比中位数偏离 1 不得超过 5%。

计时已结束但性能/预算未通过的样本也会完整封存。峰值提交内存来自子进程 Job 生命周期计数，仅作记录，不把它当作常驻量或本轮的候选内存收益。

#### 条件预算

若受影响边界原占比为 p，该边界时间减少比例为 r，新增净成本为 h，则满足模型吞吐提升至少 5% 的必要预算条件是 `p*r-h ≥ 1/21 = 4.7619048%`。本单元沿用原提案更高的 5.5% 净时间预算线，用于判断是否值得投入完整候选。

各篇、各区间独立计算：

1. `r` 取原完整工作集六个配对时间减少比例的最小观测，约 23.8890%；不用最佳样本，也不直接用平均 24.4325%。这是观测值，不是统计置信下界。
2. `p` 取本次四轮 PROFILE 中 `(准备时间+消费时间)/外部 ROI` 的最小观测，不使用 I16 等历史占比。
3. 每轮额外成本先取两者较大值：EXTRA 内直接测得的展开时间/I22 ROI，以及 `(EXTRA ROI−PROFILE ROI)/I22 ROI`，再取四轮最大值。原局部 r 已包括展开；再次扣除属于有意保守计费，避免把这项准备当成免费。
4. 再扣除四轮 PROFILE/I22 比值相对 1 的最大绝对偏离，保守处理代码和探针造成的差异。
5. 再扣除事先声明的 0.5% 转移余量。它不是缓存、调度或模型布局交互的实测上界。

因此本报告的条件净时间预算为 `p_min*r_min − h_extra_max − h_probe_max − 0.005`。两篇总体均须 ≥0.055，且各区间均不得为负；所有有效性门槛须同时通过。

即使支持，也不形成模型收益的严格下界。最关键的未证实假设是：合成工作集的局部收益可以迁移至未来模型布局。重排后的权重驻留、KV/Attention 缓存交互、真实输出提交、指针切换和失败路径，仍要等完整候选接入后检验。若所有权设计不能实现、不利交互无法控制，预算支持也不能强行放行。后续正式同场模型吞吐门槛仍为 ≥1.05×。

本轮不重新采 llama.cpp，不更新 I21 的竞争比例，不重复历史质量验收，不启用 I18/I20 已停止候选。

### I23 权重所有权接入边界

来源 `MICIUS-INT8-I23-BUDGET/docs/OWNERSHIP-FEASIBILITY.zh-CN.md`。

结论：存在可设计的私有事务接入路径，但当前模型接入尚未实现、也没有声称通过其故障注入测试。本预算包保持 I22 所有权不变。它不会因为条件预算通过就释放原 Q8 或接受完整候选。

#### 源码确认的事实

| 对象 | 当前所有者与引用 | 本轮处理 |
|---|---|---|
| 原 Q8 矩阵 | Shell 管理原分配，引擎仍借用 O/gate/up/down/输出投影等指针 | 全部保留；不能照搬 scale 的释放方法 |
| 公共 QuantDescriptor | Shell 分配；runtime 校验后复制到引擎私有 OwnedScaleBuffer | 延续 I22：成功绑定后释放 Shell 公共副本 |
| 引擎私有 descriptor | 随引擎所有，当前 GEMV 继续引用 | 保留 |
| packed QKV 权重与 scale | 引擎绑定事务建立独立副本，由 guard/引擎释放 | 保留，不能与原 QKV 重复计为热路径读取 |
| F32 embedding、norm、GGUF 映射 | embedding 与其他 Shell 缓冲/映射有各自生命周期；部分指针仍借用映射 | 保留，不能因 GEMV 重排而一并释放 |
| KV、激活与 scratch | 引擎所有；新增 10 KiB 展开区仅属 EXTRA 诊断 | 不新增 KV 或权重副本 |

源码锚点均在包内固定源码：`src/micius_runtime.cpp` 的 `Micius_BindModelTensorsV1`（488–519 行）逐项校验并复制 scale，但 Q8/F32 数据仍借用；`src/AI/AICoreEngine.cpp` 的绑定事务（683、785–807、918–945 行）先建立 candidate_layers、交换、ResetState 失败回滚、成功后移交 scale 所有权；`src/app/MiciusShell.cpp`（1305–1326 行）在绑定成功后才调用 `ReleasePublicScales`。`src/app/I22LoaderLifetime.h` 的释放函数只支持已验证的公共 scale，不能泛化为 Q8 所有权转移。

I22 的 345 MiB 原 Q8 载荷与 172.5 MiB 私有 descriptor 不等于“都有一份多余副本”。当前 I23 重排的 388.125 MiB 是整个消费矩阵的目标逻辑载荷；原 QKV、packed QKV、tied embedding、失败时旧模型的引用不能靠相减推算安全可释放量。

#### 后续完整候选必须满足的事务

1. **先验证形状、实现范围和所有引用。** I23 私有布局只用于已证明适用的 AVX2 四行消费。任意行区间、scalar/checked、draft、失败回退等仍可能引用原布局。对于未覆盖调用方，必须在退休旧存储前选择整个绑定回退；不能在释放后再临时切回旧路径。
2. **建立分配所有者清单。** 用实际 allocation identity 去重，特别是 tied embedding/output 别名；分别记录每个 owner 的消费者、容量和退休条件。每项缓冲只能由原 owner 或明确接收方释放一次。公共 ABI 的“调用方仍拥有/引擎借用”契约保持原状。
3. **全部暂存成功后再提交。** 私有引擎 staging 持有全部候选 panel 与 scale。形状、数值、分配预算或初始化任一失败时，销毁 staging，原模型和 I22 存储保持有效。分配并非无成本：暂存整套 panel 可能增加约 388.125 MiB 瞬时申请量，应单独测加载峰值与加载耗时。
4. **提交后再退休。** 成功替换所有可达消费指针、完成 ResetState，并向私有 Shell 接入层返回已提交的 owner 清单后，Shell 才可退休不再被任何路径引用的原分配。保留原布局的未覆盖路径必须明确计入常驻成本，不允许默认长期保留整套 345 MiB 权重影子。
5. **失败与重复生命周期检查。** 必须实测逐阶段分配失败、绑定失败、重绑、reset、错误输入、析构与别名；确保失败不改变旧模型，成功不留悬空引用或重复释放。默认关闭时需恢复 I22 输出与行为。

以上是实施约束，不是已完成的所有权交接代码。可行性来自现有 `candidate_layers` / guard / ResetState 回滚结构和私有 Shell 装配入口；安全性最终必须由具体引用替换实现及测试证明。如果只能通过大范围公共 ABI/加载器改造来实现，按原 I23 提案停止，而不是把内存副本当作免费的权宜之计。

本预算观察程序的生命周期检查只证明“加入定向计数和额外展开后，原 I22 的输出、reset 和重复加载行为保持正确”，不把这项结果写成未来 panel 所有权事务已经验收。

#### 对至少 5% 模型收益的意义

令当前模型中对应完整边界的原耗时占比为 `p`，该边界在实际模型中的时间下降比例为 `r`，边界外新增开销及对其他路径的净影响占原总时间的比例为 `h`，则模型时间比为 `1 - p*r + h`。整体吞吐提升至少 5% 需要净省时间至少 **4.7619048%**；原定进入完整候选包的预算门槛更高，为 **5.5%**。

本次测得的是合成工作集中的 `r`，不是实际模型中的 `r`，当前 `p` 与 `h` 也未测定。若局部 24.4325% 的下降能够迁移、且 `h=0`，达到 5.5% 预算要求 `p≥22.5110%`。若改用六对中最小的 23.8890% 下降，并假设边界外额外开销为原总时间的 0.5%，则要求 `p≥25.1162%`。这只是有明确假设的敏感性计算；最差观测对不是统计置信下界，0.5% 也不是本轮测得的外部开销。

因此，本轮已补上“完整权重工作集下，局部实现是否有足够明显收益”的证据。剩余缺口是实际模型内的占比、缓存/调度环境与新增成本，以及加载器所有权替换的可行性。不能沿用 I16 的旧矩阵占比，也不能将单次合成扫描节省约 5.23 ms 写为模型每 token 节省量。

下一阶段仅针对上述边界补充当前模型预算与所有权证据，包含观察开销控制、默认关闭恢复 I22、失败清理和不长期保留整套权重影子的约束。达到原定 5.5% 预算后，才进入完整 I22/I23 模型对照包；最终仍由用户执行正式采样，以同场整体吞吐至少 **1.05×** 判断。泛化剖分保持暂停，本次不更新正式 llama.cpp 竞争比例。
