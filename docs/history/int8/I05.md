### I5 implementation and evidence boundaries

来源 `MICIUS-INT8-I25-P1/micius/docs/INT8_I5_IMPLEMENTATION.md`。

#### Parent and change scope

The independent I5 candidate is extracted from sealed I4, identified by its source ZIP SHA-256 in `I5-MANIFEST.json`. The sole modified existing file is `scripts/run_i4_nll.py`. Its previous per-entry guard missed extra source files that CMake could discover; it now calls `i5_common.verify_source` using the current I5 manifest when present. The new guard compares complete path-to-hash dictionaries before any I5 output creation or build. It includes all files in source, include, test, script and tool directories, plus CMakeLists and CMakePresets. Only `.pyc` inside `__pycache__` is ignored; a `.cpp` inside such a directory is still rejected. Missing or modified members are rejected too.

All existing C++, headers, public ABI, preset/build declarations, tokenizer resources, I1 arithmetic, original v0.6 ZIP and prior historical evidence retain their I4 bytes. The I4 CLI option names and private policy flags remain intentional: I5 changes orchestration and data, not the native evaluator. Historical I4 source/result archives remain untouched outside this new candidate.

#### New components

- `scripts/i5_common.py`: streaming hashes, durable atomic JSON writes, complete source-set validation and completed-job payload verification.
- `scripts/prepare_i5_corpus.py`: original-resource snapshots, deterministic disjoint WikiText selection, fixed Gutenberg slices, I4 tokenizer compatibility reuse, round trips, text/ID manifests and no-overwrite verification.
- `scripts/analyze_i5.py`: vectorized F64 NumPy log-sum-exp over every original F32 vocabulary value, strict per-position metadata checks, matched primary/subset/tail comparisons, predeclared gates and descriptive statistics.
- `scripts/run_i5_nll.py`: mandatory frozen-identity preflight, fresh builds, CTest, historical/reset/prefix/all-F64 controls, independent per-job score checks, resumable seals and complete result packaging.
- `tests/i5_evidence_tests.py`: source contamination, evidence corruption, unsafe resume and acceptance cases where an acceptable global mean hides a failing document or late position band. The small score fixture uses analytic stable sums and is compared with the unchanged scalar I4 analyzer as well as NumPy.

#### Execution and interruption model

The global run identity binds all 83 executable source files, all 66 input data files, the frozen protocol and specified GGUF. Binary hashes bind each of five native configurations. Each completed-job seal additionally binds token bytes, CPU index, policy and job name, with an exact set of three payload files: scores, raw logits and independently recomputed analysis.

The runner saves command start and exit state and atomically saves job state. A complete payload is sealed only after a successful process exit and independent raw-logit verification. If interrupted in an unsealed state, it retains the old attempt and creates another directory on resume. Verified completed jobs are not overwritten. A process-wide Windows file lock prevents concurrent writers for the same run; two quality workers inside one runner use separate directories and serialized metadata writes. Their different CPUs do not establish any performance claim.

The archived full result includes all successful raw logits and any retained prior attempts, commands, compiler/build/test records, fixed resources, protocol, binary hashes, job seals and complete file identities. In-memory reports are not the sole evidence. A separate `archive-receipt.json` references the finished ZIP's SHA-256 and is outside that ZIP to avoid self-reference. An archive interrupted during writing is preserved for inspection rather than silently overwritten.

#### Interpretation

Prefix/band changes combine increasing history and changing target content. The additional matched-tail probe holds the last 256 targets fixed and changes only supplied history, while F64 and I1 remain paired on each history. Its difference of paired NLL deltas describes these four probes and is excluded from primary totals. It does not localize a specific layer or establish a universal propagation law.

The primary engineering screen is frozen before any I5 model scores. Mixed policies use a preselected four-document subset; their averages cannot be compared with a full 16-document mean. Tail exceedance rates and stratified paired document-bootstrap intervals are descriptive; fixed nonrandom selection prevents a population noninferiority claim. A successful screen authorizes a recommendation for the next review, not a default-policy change or stable integration.

### MICIUS I5：扩展固定文本与较长上下文质量评估 — 2026-10-12

来源 `MICIUS-INT8-I25-P1/micius/docs/INT8_I5_RESULTS_2026-10-12.md`。

**I5 已完成。I1 通过全部预先固定的工程筛选，可以进入单独的有限性能与工程准入评估。本轮没有作出稳定集成决定。**

本轮从已封存 I4 独立派生。主比较使用 16 份固定英文文本，每份 2,048 个真实 next-token 目标，共 32,768 个目标／配置，是 I4 目标位置数的 16 倍；最长已测输入历史为 2,048，是 I4 的 8 倍。F64 与 I1 始终消费同一份 gold token 历史，逐篇重置，没有生成反馈、额外 BOS/EOS 或跨篇目标。

#### 中断恢复核验

28 份已封存结果逐项核对身份和散列后复用。原来未完成的两项在新目录用同一配置执行，其残留不参与评分。

两份中断残留含 1,854 行完整长度的原始 logits（364,511,232 字节），没有完成记录，且落盘的完整分数记录数少于原始行数。这些残留按原散列保存在全量 ZIP 中，**不计入任何评分或完成数量**。原命令账本保留两个 RUNNING／未知退出码记录，不能误读为当前仍在运行；82 条已成功结束的命令另有完整记录。

恢复没有改选语料、修改阈值或改动评估实现。两份残留的全部 1,854 行原始 logits 与成功重跑的对应前缀逐字节一致。完整恢复证据见 `docs/i5-evidence/resume-integrity.json` 和 `interrupted-prefix-parity.json`；收尾再次检查原命令账本、28 个复用完成标记与两份残留均未改变。收尾恢复核验器另外通过 8 个合成记录案例（1 个合法案例、7 个拒绝案例），覆盖伪造旧命令成功、失败重试、身份变化、残留篡改及重跑已完成任务；这些不是额外模型实验。

#### 实现、验证与交付身份

- 修复候选源码集合校验：额外、缺失、内容修改的源码均在构建前拒绝。专项测试还覆盖隐藏在 Python 缓存目录中的额外 C++、损坏结果、错误目标／路由／FP 状态、不安全断点复用，以及总体均值通过但逐篇或后段退化失败的情况。共 10 项测试方法，含额外负例子项。
- I5 初始运行的五个新构建配置各通过 13 项 CTest，共 65 次执行；恢复时核验并复用二进制，没有重跑这些原生测试。10 项证据测试套件在初始运行和恢复时各执行一次。本轮 C++、公共头文件、ABI、CMake、preset、F64 与 I1 算术均与封存 I4 逐字节一致。四个策略的 I4 32 行历史前缀、真实模型 A/B/A 重置、256／512／1024 行前缀复跑及 2048 行 F64_ALL 对照均通过原始 logits 字节比较。
- 83 项源码、66 项输入数据及固定协议在运行前后和收尾核验时一致。每个已完成片段先由 NumPy F64 独立复算完整 F32 logits，再用包含模型、源码、输入、协议、二进制、CPU 与逐文件散列的完成标记封存。
- 成功完成的 **61 个任务**包含 **89,920 行原始 logits、4,419,747,840 个 F32 值**，覆盖主比较与全部对照；另有上述中断残留单独保留。C++ 与独立 NumPy 逐位置 NLL 最大绝对差为 **3.5527136788005009e-15**。
- 收尾检查流式验证完整 ZIP 的 **507 个成员**，完整成员集合、SHA-256、解压 CRC 和落盘原件一致；另外从 C++ 逐位置分数用独立标准库聚合重新计算主结果与全部筛选门槛，结论相符。该收尾检查没有再次运行模型，也没有把历史测试计为本轮执行。

#### 阶段决定

I1 在本轮扩展固定英文语料和最长 2,048 的已测上下文范围内通过全部预设筛选。下一项可以安排有限、预先固定的 I1/F64 性能与工程准入评估，结合真实运行时成本决定后续取舍。

该决定不扩大为任意文本、其他语言／模型、完整 8,192 上下文、全运行时 sanitizer、性能验收或稳定集成批准。本轮并行质量作业的耗时只用于执行记录，不能视为吞吐基准。
