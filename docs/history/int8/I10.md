# I10 · 有序 Attention Value64

**采用。** I10 相对同场 I1 吞吐提升 6.5034%。前 256 个位置提升 1.0556%，后 1,024 个提升 8.5248%。

64 维路径把累加器保留在寄存器，保留每个时间步的 F64 运算及 F32 舍入，其他维度和异常回到参考路径。长段收益与扫描历史 V 的机制相符。

### I10 实现与验证边界

来源 `MICIUS-INT8-I10/docs/IMPLEMENTATION-AND-VALIDATION.md`。

#### 依据与改动

I9 的完整复核已通过。原 I1 的 Attention Value 耗时占比约 18.60%；候选只处理这一热点，不改变其余注意力阶段、量化或矩阵消费。单一 Value 优化无法解释或消除所有约 1.95 倍的端到端差距；矩阵消费仍是后续主优化方向。

候选源自嵌入的原始 I6 ZIP，其完整文件集合保存在 `upstream/I6-SOURCE-FILES.json`。原有 415 个文件中，只改 CMakeLists.txt 和 AICoreEngine.cpp；新增一个私有头、一个实现与一个内核测试，共 418 个文件。原有内核和所有公共头保持逐字节一致。新 CMake 开关 `MICIUS_I10_VALUE64` 默认 OFF；OFF 时新实现不参与编译，16 个原编译单元与 I9 的参数一致。

ON 时，64 维、无输出别名、异常被屏蔽的路径使用八个 F32 SIMD 累加器。每个时间步仍按原先顺序：将前一步 F32 精确提升到 F64，进行 F64 FMA，检查 F64 值是否有限且在 F32 范围内，再舍入为 F32。不会跨时间步保留 F64 累加结果。

一个不发出指令的编译器寄存器约束，让已舍入的两半保持打包状态，防止 LLVM 将其拆成 16 个活跃 XMM 值并溢出到栈。最终链接机器码通过配套 PDB 定位热循环：每个时间步 16 条 F64 FMA、16 条 F64→F32、32 条 F32→F64 转换，循环内无栈访问。函数入口/出口仍有 Windows ABI 要求的寄存器保存恢复，不能称为“完全无栈”。

其他维度、无效参数、范围计算不能安全表示、输入输出重叠、未屏蔽浮点异常均回退到原实现。候选在发现数值错误时，恢复进入前 MXCSR，并重放原内核，以保持原状态码、部分输出和浮点异常标志。正常路径不分配堆内存、不增加 KV 缓存；只使用固定数量的寄存器和函数栈空间。

#### 已完成的轻量检查

- 680 个候选内核检查：独立按时间顺序的 F64 FMA/F32 参考、原实现逐字节对照；长度至 8192；特殊值、溢出后舍回有限值、四种舍入模式及 FTZ/DAZ、未屏蔽异常的回退、输入保持不变、别名、输出哨兵和 Windows 保护页。
- 原 Attention Value 的 96 个对照形状、原 W8A8 GEMV 的 425 个用例和 ABI/生命周期测试通过。
- 58 次合成模型命令，覆盖 head_dim 32 和 64、128/2048 步、完整 logits、计时输出对照、重复执行、错误输入，以及两种 MICIUS 配置各八轮加载/释放/重置检查。
- 8 项运行控制测试及 11 项模拟流程检查，覆盖计时顺序、慢样本保留、缺失/重复/非有限时间拒绝、退出码与参数身份、资源记录与封存散列绑定、数值门槛前停止、速度/内存未达标、中断状态保留及双 ZIP 成员校验。
- 三份正式程序的完整反汇编不含 VNNI；候选与基线的共享编译单元仅允许私有开关差异。有效 CPU 宏须与 I9 完全一致，保留原 AVX2/FMA/native 设置。

检查记录分别进入准备目录的 `contracts/`、`logs/` 及工作目录的 `selftest/`。交付前还会在独立解包目录走完 `prepare` 并复核 ZIP 的完整成员集合和散列。

#### 合成内核速度观察（不是正式验收）

另有一个独立的合成数组小测量，固定 64 维、步长 320、CPU 4，四轮交换顺序，比较原内核和候选。32 / 256 / 2048 时间步的配对中位速度比分别约 0.9606 / 0.9601 / 1.3010。所有记录保存在 `validation/SYNTHETIC-KERNEL-ONLY.json`。

该测量使用独立小型测试程序与循环复用的合成数组，缓存行为不同于完整模型。它说明短序列可能略慢、长序列存在可测收益，不证明 I10 的端到端表现。正式协议因此同时检查总体、每篇、每个上下文区间和内存；不因这组微测量跳过任何区间。

#### 正式证据仍待用户采样

已验证的真实输出是 I9 历史轨迹；当前没有运行 I10 的目标模型，也没有预填 I10 速度或通过状态。用户运行后的 6 条完整轨迹和 36 条正式计时才决定本候选是否达到固定门槛。I10 与 I1 要求逐字节一致，因此若门槛通过，两篇固定文本的 NLL/PPL 应完全相同；这仍不外推到所有文本的质量验收。

峰值提交内存只证明本次进程生命周期中的峰值范围；合成生命周期检查只覆盖合成形状和八轮操作。未测物理工作集、温度、有效频率或所有真实模型长时间泄漏。程序在结果中保留这些证据边界。

**比较范围与方法**

SmolLM2-360M-Instruct Q8_0，两篇固定自然文本，每篇 2,048 个预测位置；单线程，绑定逻辑 CPU 4，连续上下文。三组均无 VNNI，保留既定 AVX2/FMA 等配置。I1 和 LLAMA_OFF 使用冻结的 I9 对照程序；I10 仅启用私有 Attention Value64 候选。

每篇六轮覆盖三配置的全部六种运行顺序，共 36 条正式计时。总体加速比先计算每轮 I1 耗时 / I10 耗时，再取每篇中位数，最后取两篇的几何平均。绝对吞吐率另取每组六次的中位数，不能用表中经四舍五入的吞吐率比值替代配对统计。保留全部样本，无重试、筛除慢样本或混入历史计时。

**剩余差距和后续方向**

同场 LLAMA_OFF 相对 I1 的配对速度比为 **1.938994×**；相对 I10 为 **1.820502×**。I10 达到本轮 LLAMA_OFF 吞吐的约 **54.93%**，仍需约 **82.05%** 的进一步吞吐提升才能追平这一无 VNNI 对照。当前有效优化应保留，剩余性能与内存差距也需继续处理。LLAMA_ON 仍是主线最终追赶标尺，本轮没有新采集 ON 结果，不能拼接 I8/I10 的跨日期比值构造新的 ON 对照结论。

建议下一工作单元以 I10 为候选基线，优先考察 I9 已识别的 Attention Score 热点，固定一个可区分的无 VNNI 改动，并继续约束输出、全部上下文区间和资源代价；矩阵消费仍保留为主要优化方向。新候选的收益需重新同场测量。此处仅提出后续目标，没有启动 I11、修改稳定默认或追加真实模型采样。
