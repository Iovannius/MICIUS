### I7 中 VNNI 优势与剩余实现差距的证据边界

来源 `reports/I7-VNNI-SCOPE-CHECK-2026-10-14.md`。

现有 I7 已测得 llama.cpp 相对 MICIUS I1 的长程配对速度比为 1.987399547847531，128 步固定前缀为 1.5100106019766553。尚无关闭 VNNI 的 llama.cpp 正式计时，因此当前不能给出 VNNI 的实际加速倍数，也不能把 1.9874× 全部归因于 VNNI。

本次只读核对确认了 I7 llama.cpp 的 VNNI 编译路径：

- 冻结适配器启用 `GGML_NATIVE=ON`；构建日志及源码显示 Clang CPU 后端使用 `-march=native`。
- CMakeCache 中 `GGML_AVX_VNNI=OFF` 不代表这份 native 构建关闭 VNNI；该开关位于非 native 构建分支。
- 实际封存二进制的 `ggml_vec_dot_q8_0_q8_0` 中存在三处 VEX 编码的 `vpdpbusd ymm`，证明相关 Q8 点积路径已编译为 256 位 AVX-VNNI。这是静态二进制证据，不是动态采样或该函数耗时占比。
- 同机 Clang 特征探针中，`-march=native` 定义 `__AVXVNNI__`；追加 `-mno-avxvnni` 后，预定义宏差异只有移除此宏，AVX2/FMA/F16C 等保留。正式构建仍须核对全部编译命令及最终反汇编，不能只凭探针或 CMake 选项判断。
- 上游 x86 Q8 点积源码在有 AVX-VNNI 时使用 `_mm256_dpbusd_avx_epi32`，否则使用 maddubs/madd 的组合。这不能直接换算成整个模型的固定加速倍数。

静态检查证据保存在 `reports/i7-vnni-evidence-2026-10-14/`。被检查二进制 SHA-256 为 `37f2ecec2fd27def4bd5f5959101a63f5ab643bf43adbad0bbf767740421ce75`。本次没有编译新的引擎、运行目标模型或修改已封存 I7。

需要补充的最小工作是同一份 llama.cpp 0.6.0 的 VNNI 开/关对照。保留相同编译器、源码、优化、其他 CPU 特征、重排策略、F32 KV、线程、绑核、输入与计时范围；只改变 VNNI 可用性，并以最终指令检查确认。Clang 官方选项依据：[Clang command line argument reference](https://clang.llvm.org/docs/ClangCommandLineReference.html)。

建议同时放入原 I1 二进制，形成三组：llama.cpp VNNI 开、llama.cpp VNNI 关、MICIUS I1。对 SmolLM2 使用原两篇固定文本、2,048 步主比较和 128 步前缀辅助比较、各四轮，共 48 条正式计时。三组在同一轮交错测量，避免用不同日期的绝对吞吐相除。Qwen 单独扩展不能帮助判断当前 MICIUS 的同模型差距，因此不属于这项最小比较。固定输入的非计时输出验证和两构建的数值一致性检查应在正式计时前完成；数值差异须保留并解释，不能忽略后继续称为完全相同的数学路径。正式模型采样仍由用户 Bash 终端执行。

设同一配对样本内速度分别为 V_on、V_off、V_I1：

`VNNI 收益 S = V_on / V_off`

`关闭 VNNI 后的参考差距 G = V_off / V_I1`

`总速度比 R = V_on / V_I1 = S × G`

该乘法关系在单个配对样本内成立。中位数并不保证乘法可分解，因此正式报告应从每轮直接算 S 和 G 后分别汇总；不能将来自不同实验、不同长度或不同模型的汇总比值直接相除并当作实测。

仅为说明比例：若同样工作负载的 VNNI 收益为 1.20×，则以 I7 的 1.9874× 作粗略参照，剩余差距约为 1.656×；这是假设算例，不是 VNNI 测量结果。128 步与 2,048 步必须分别测量，因为 VNNI 影响的工作占比可能不同。

关闭 VNNI 的 llama.cpp 可以作为成熟 AVX2 实现的整机参考，但剩余差距仍包含浮点精度、数据布局、重排、注意力、调度等差异。MICIUS I1 的 INT32 点积后仍采用 F64 缩放和累加，上游 Q8 点积使用 F32/FMA 路径。因此该结果不能直接定义为 INT8 点积内核的纯实现差距，也没有自动给出“性能合格线”。本文件只明确现有证据和建议补测目标，不代表补测已经执行。
