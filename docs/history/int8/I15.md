### I15 numerical contract and limits

来源 `MICIUS-INT8-I15/docs/I15-NUMERICAL-CONTRACT.md`。

Only the private Value dispatch changes. The old I10 entry remains compiled and
unchanged; I11 Score, I13 W8A8, preparation, public headers and presets are unchanged.
I15 is OFF by default. The delivered build audit checks parent source identity,
the complete compilation set, shared flags, the final linked loop and absence of VNNI.

For each dimension the recurrence is exactly:

`a[0] = +0f; a[t+1] = F32(FMA_F64(F64(p[t]) / sum, F64(v[t]), F64(a[t])))`.

Neither the order of time steps nor an intermediate F32 rounding is removed.
The intermediate F32 value is widened only at the following update. In particular,
an F32 subnormal at the final step is not prematurely consumed under DAZ. The
scratch copy at a 32-row boundary is a float store/load, not a conversion.

The optimized range is n in [128,8192], dim=64, disjoint output, valid strides,
finite positive sum, and masked floating-point exceptions. A 32-row scratch buffer
holds the original double divisions; each normalized probability must be finite
with absolute value <=1. Each eight-float value load must be finite with absolute
value <=2^100. These bounds are checked on the supplied data, not assumed from
model quality. A quiet NaN fails the ordered comparison as well.

With |q|<=1 and |v|<=2^100, an exact update has magnitude at most |a|+2^100.
Allowing every F64 and F32 rounding to increase magnitude, a conservative bound
is n*2^100*(1+2^-22)^(n+1), plus subnormal rounding terms. For n<=8192 this is
strictly below 2^114; the subnormal terms are negligible even under upward
rounding. This leaves over thirteen exponent bits before FLT_MAX. FTZ/DAZ cannot
increase the magnitude of the affected subnormal operands/results. Thus no
successful bounded update can trip the old finite/F32-range check. This permits
one eight-float input check in place of two four-double result checks.

Any failed bound causes replay, even if the original operation would be valid.
Output is untouched until all tiles succeed. Before replay, MXCSR is restored to
its entry value; the old entry reproduces status, partial output and exception
flags. Non-default rounding modes and FTZ/DAZ are preserved. Unmasked exceptions
use the original entry directly to preserve trap ordering. Inputs must still be
valid readable arrays of the supplied extent, as required by the old contract.

On success, arithmetic operations affecting the result are unchanged. Additional
input comparisons do not introduce a new exception on finite normal data. For
subnormal operands, the original F32-to-F64 conversion or F64 FMA consumes the
same operand; DAZ/FTZ and accumulated flags are compared by contract tests. On any
non-finite/bound failure, speculative flags are discarded before original replay.

Testing covers an independently ordered scalar F64/F32 oracle, the old entry,
all rounding modes and FTZ/DAZ combinations, arbitrary float bit patterns, tile
tails, bound edges, long cancellation, aliased output, guarded memory, numeric
errors/partial output and exact unmasked fallback. These tests are empirical
coverage, not an exhaustive proof of every bit pattern. Formal fixed-text logits
must still match the accepted I13 trace before any performance samples.

Two fixed local arrays hold 64 floats and 32 doubles (512 bytes total). Compiler
frame bookkeeping is additional; there is no heap allocation or persistent cache.
The final time loop must have eight F64 FMAs, eight F64-to-F32 conversions, sixteen
F32-to-F64 conversions and four eight-float bound comparisons, without stack
accesses. This structural check does not establish target-model performance.

### I15 正式结果复核 · 2026-10-19

来源 `reports/I15-review-20261019-180934-0dee06c8/I15-RESULTS-REVIEW.zh-CN.md`。

**通过：I15 满足预设数值、计时稳定性、端到端收益和资源门槛，接受为下一工作单元的实验基线。稳定产品默认不变。**

依据运行 `i15-20261019-180934-0dee06c8`。两篇固定自然文本各2048个预测位置，I13、I15、llama.cpp 0.6.0 LLAMA_OFF 三组；单线程CPU 4、显式无VNNI。每篇六轮、六种排列，共36条同场计时；全部保留，无自动重试、删除慢样本或历史计时拼接。

I15 相对同场 I13 的配对速度比为 **1.032239201×**：吞吐提升 **3.22%**，同等工作耗时减少 **3.12%**。统计按各轮配对、篇内中位数、跨篇几何平均计算。下表tok/s是每程序六次吞吐的中位数，两种统计不可混用。

| 文本 | I13 tok/s | I15 tok/s | llama OFF tok/s | I13/I15 配对速度比 |
|---|---:|---:|---:|---:|
| s00 | 25.6872 | 26.4988 | 35.2774 | 1.032154 |
| s08 | 25.6971 | 26.5170 | 35.3295 | 1.032325 |

| 位置区间 | I13/I15 速度比 | 吞吐提升 | llama OFF/I15 吞吐比 |
|---|---:|---:|---:|
| 0–256 | 1.001744 | 0.17% | 1.124317 |
| 256–512 | 1.010360 | 1.04% | 1.176977 |
| 512–1024 | 1.026299 | 2.63% | 1.271980 |
| 1024–2048 | 1.042015 | 4.20% | 1.416805 |

首段跨篇收益约 0.17%，尾段约 4.20%。s00首段速度比为 0.998885，即约0.11%的轻微回退，仍在预设0.98门槛以内；不应写成每个区间都变快。

收益随上下文增长而增大，与本轮针对Value逐时间累加的改动相符。此次无分项探针，因此可以确认该候选改动的端到端收益，不能从总时间直接量出Value自身的加速率、访存瓶颈比例或剩余可回收时间。开发微测的1.24–1.36倍不是整模型速度承诺。

同场 llama OFF 吞吐是 I15 的 **1.330392 倍**；I15 达到其 **75.17%**。从I15自身出发还需提升 **33.04%** 才能追平，相对llama的吞吐短缺为 **24.83%**。两者分母不同。同场I13与llama的比值为1.373617，I15缩小了差距，但尚未追平。此轮不含VNNI开启版，不能据此宣布达到LLAMA_ON目标。

尾段剩余吞吐比仍为 1.416805，大于首段 1.124317。这保留了继续研究上下文增长成本的理由，但不能把全部差额归给Value，也不能将I14旧热点占比当成I15的新成本结构。
