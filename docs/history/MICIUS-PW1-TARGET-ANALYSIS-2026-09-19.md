## 3. 机器码与调用路径

以下均为实际 prevalidated 双行、每行 32 列完整 block 的内循环，属于当前真实模型使用的路径。

| 项目 | r1 prepared Q8 | PW1 prepared F64 weights |
|---|---:|---:|
| 静态指令数 | 98 | 66 |
| 编码字节 | 486 | 385 |
| 权重 `vpmovsxbd` | 16 | 0 |
| 权重 `vcvtdq2pd` | 16 | 0 |
| activation `vcvtps2pd` | 0 | 0 |
| activation `vmovupd` | 8 | 8 |
| `vmulpd` / `vaddpd` | 32 / 16 | 32 / 16 |
| block scale `vcvtss2sd` / broadcast | 2 / 2 | 2 / 2 |
| 内循环栈访问 / CALL / FMA / EVEX | 0 / 0 / 0 / 0 | 0 / 0 / 0 / 0 |

新内核以 `vmulpd` 的内存操作数读取 16 组 F64 权重；它们不是零成本加载，只是没有单独的 `vmovupd` 权重指令。两个 scale 仍分别加载、转换并用于原顺序的乘法。输入已经是 r1 准备好的 double，不能再把旧 B 的在线 activation 转换描述套到 PW1 上。

**预展开确实删除了那 32 条权重转换。** QKV 与 O 的 F64 主循环字节完全一致；NONE/QKV/O 的 Q8 主循环字节也完全一致，而且与已审查 RB1 ThinLTO 的 r1 prepared 对应主循环逐字节相同。没有发现“为候选构建时把剩余 Q8 内核编坏”或“权重实际上又在热循环转换”的现象。

静态指令数减少不等于执行周期减少。此处仅证明代码生成达到了预期表示替换，不能把 32/98 写成转换成本占比。

调用层确有有限增加：GEMV lambda 从 376 B 增至 494 B，用于检查 prepared-weight 指针和选择入口；预验证 weight wrapper 为 385 B，Q8 wrapper 为 351 B。两者各有一次内循环之外的正常 kernel CALL。forward → lambda → wrapper → kernel 的调用层数没有增加；forward 的静态直接 CALL 位置均为 17 处，不能把它当作每 token 的动态调用次数。

源码与新目标代码未见 per-token 权重展开；展开只在绑定中发生。activation 仍按 r1 组织准备，FFN gate/up 共享一次输入快照。这里没有发现新增的逐权重验证扫描、重复准备或浮点累加器 spill。没有单独测量新增 dispatch 的周期成本，因此不宣称其精确成本为零；普通 wrapper 的栈帧/参数读写也不能称为热循环 spill。

## 4. 为什么旧 B 能赢，PW1 在 decode 中反而输

先前 RB1 的模型形状实验反复访问同一组矩阵与合成输入；QKV、O 的 +16.90% / +21.14% 属于那个访问与计时范围，并以旧诊断 A 为分母。PW1 的分母已是 r1 prepared 实际路径，访问的是整个真实模型。两批数字不能直接相减或当作同一 kernel 的回归幅度。

完整 decode 每次经过全部层及 FFN、LM head 等权重。某层 QKV/O 在下一个 token 再使用之前，已经穿过其余大量矩阵；单个矩阵在微基准中的反复复用条件不成立。PW1 仅限制了“哪一种投影”及分配预算，尚没有让这些展开结果在完整 forward 中获得同样的缓存驻留条件。

| 所选组（32 层） | 原 raw Q8 范围 | 新 raw F64 范围 | 每 token 逻辑权重读取范围增量 | 保留 Q8 时额外分配 |
|---|---:|---:|---:|---:|
| QKV | 46.875 MiB | 375 MiB | 328.125 MiB | 375 MiB |
| O | 28.125 MiB | 225 MiB | 196.875 MiB | 225 MiB |

上述范围由实际形状和每权重的 1/8 B 计算；scale、activation、KV 等另算。预展开后选中 GEMV 读取 F64，保留的原 Q8 不因此同时再被该 GEMV 读取。所以“额外分配”和“原始权重读取范围增加”必须分开。

**最符合当前证据的解释是：减少拓宽的收益被更大权重访问范围及完整模型的缓存/内存访问代价抵消。** QKV 访问放大更多，同时观察到更大的延迟损失，这与解释相符。

这仍是由代码、数据流和端到端测量支持的归因推断。本批没有 PMU、实测 DRAM GB/s、cache/TLB miss 或逐算子分段时间，不能继续声称已经分别证明“DRAM 带宽占多少”“cache miss 占多少”。也不能用额外字节数除以时间差，冒充 DRAM 带宽。权重缓冲实际对齐/页映射也没有在本批日志中记录。

结论是这个整组选择策略在当前目标和模型上没有净收益；旧 B 的驻留收益继续有效。仅依据矩阵类型或单矩阵尺寸来决定生产启用，证据不足。512 MiB 是容量保护，不是性能保证。

## 5. 19.48 tok/s 与历史 9.40 tok/s

本批 NONE 未启用权重展开，故 **19.4846025 不能计为 PW1 的优化收益**。它也不能直接与不同日期 r1 的 9.403544 相除来宣称当前工程已经被这次工作加速约一倍。

本轮只做有边界的对应检查：历史 prepared ON 与当前 NONE 的 AICoreEngine、ReferenceGEMV、ReferenceAttention、MiciusShell 实际编译选项相同，除新增的 `PW1_MODE=0` / budget 宏；工具链版本相同。Q8 数值源文件未变，本批 Q8 主循环也与此前 RB1 对应代码一致。PW1 CLI 新增了加载前固定 CPU、加载计时和独立 parity 模式，NONE 保留原 decode 计算路径。

现有材料没有记录两批的频率、功耗、温度、后台活动等足以解释绝对速度变化的环境数据，也没有同批旧 EXE 对照。因而这个跨批差异 **尚不能定因**。它不使本批交错 NONE/QKV/O 的负收益失效，也不要求重启整个基线验收。

如以后确实要归因跨批变化，最小补充是保存旧 EXE 身份并与当前 NONE 同批、同协议交错测量，记录必要运行状态。当前 PW1 决策不依赖先解决这个问题，本轮没有追加该实验。

## 6. 本轮决策及下一步

1. **PW1 QKV/O 均不晋升。** 保留默认 NONE；不合并为已接受的性能优化，不删除负结果，也不把 correctness PASS 改写成实现失败。
2. **未确认需要修复的新数值或构建缺陷。** 本轮没有修改运行时源码或重新编译候选，仅分析现有归档并更新状态。新目标代码审查已经完成上述明确范围。
3. **下一项观察必须改变能区分原因的条件。** 若继续追究这一机制，先复用已有比较内核做“一份相同矩阵反复消费”与“多层矩阵轮转、保持完整模型复用距离”的对照，并保持准备、输入和消费次数同口径；或取得 decode-only 的 cache/TLB/内存计数器。目标是区分驻留复用与表示读取放大，不能再重复本批六轮去追正收益。新增工具尚未实施。
4. **继续本阶段的预转换研究时，应先筛选更小表示及真实复用条件。** 例如 raw int8 精确转 F32 再进入原 F64 算术，在数值上可保持整数值，但它仍需要 F32→F64、且保存 4 倍 raw 权重；本批未验证它，不提前称为可采纳优化。每 token 展开一次、消费一次也没有免费摊销依据。
5. 对后续阶段保留的工程信息是：canonical Q8 与可选表示可分离；绑定期准备、整体预算/失败回退和 Context 绑定生命周期可表达清楚；**表示选择必须考虑完整访问序列和复用距离**。跨 Context 共享模型尚未实现。W8A8/VNNI 不在本轮推进范围。

本轮可审查单元已完成：PW1 目标正确性及负收益得到确认，转换移除与调用边界得到目标机器码支持，内存子系统的详细成本分解和跨批绝对速度变化明确保留为未知。原阶段目标不因这个负结果自动改写。
