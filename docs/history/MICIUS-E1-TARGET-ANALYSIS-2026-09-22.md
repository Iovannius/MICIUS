原 Q8 循环编码 SHA-256 `11a01ac101cf528cc5d5edec3080c4c35ed4a43baf0a1349b24516d44cf43e3a`，与已验收 D1 BASE 逐字节相同。收益没有通过改弱本批 Q8 主循环取得。

E1 循环为 VA `0x140099d30`～`0x140099ee9`（末地址不含），编码 SHA-256 `0c14ed4adb8c4ca2be3468cfd976e53670347e19b545f9f86cfcdd9ba0a1abf0`。栈数据流可明确分类：

| 写入 → 读取地址 | 栈槽 | 内容 |
| --- | --- | --- |
| `0x140099d6f` → `0x140099dd0` | rsp+0x40 | 本 block activation 第 8～11 列的向量临时值。 |
| `0x140099d7e` → `0x140099e35` | rsp+0x60 | 第一输出行第 0 条链的中间累加值；在同 block 后半段 FMA 中读取。 |
| `0x140099e0e` → `0x140099ec6` | rsp+0x40 | 第一输出行第 3 条链的中间累加值；复用已经释放的 activation 栈槽。 |

这三组确为向量 spill/reload，其中两个为中间累加值；不能解释成旧 checked 路径的整数边界读取，也不是函数入口的 ABI 保存。三次写入及三次读取各 32 B，静态上每个双行 block 多访问栈 192 B；不把它当作额外 DRAM 流量或已测缓存带宽。

算术指令少了 16 条，但新增四条独立向量搬运，另两次读取折入 FMA 的内存操作数，故总指令只减少 12 条。静态计数不能分解周期贡献；现有 +15%～+19% 是包含 spill、wrapper 与分派的整体净效果，不能归为纯 FMA 吞吐或声称 spill 消除后必达某个倍率。

`e1_repeat` 的不透明间接调用、状态分支和循环计数保留；`measure` 的两次时钟调用之间仍调用它，输出验证在计时后。Q8/E1 的外层适配和 wrapper 均有正常 CALL；“循环内无 CALL”不扩大到整个调用链。选定热循环无 EVEX，也不扩大为整个 native EXE 的 Haswell 兼容声明。

**对既定目标及下一工作单元的影响**

本批支持继续投入 E1，并提供了一个具体的修正点；没有发现数值正确性失败，也没有证明运行时或编译器存在普遍缺陷。下一单元优先针对候选临时值生命周期/调度做一次定点修正，保持本批 E1 与原 Q8 两个对照；目标是减少上述 spill，同时保持每条累加链的项顺序和精确融合条件。目标机器码及同批测量须确认修正是否真正奏效，不只看源代码或 GCC 本地结果。

有价值的候选随后才接入私有模型元数据：资格与权重所有者同生命周期，在 binder 成功提交时建立，非法输入/失败提交不留下可用资格，非适用矩阵回退；进行对应数值/运行时测试、固定 token 完整 logits parity 及同批 decode 比较后才能晋升。这些尚未实施，不能把本批结果改写为运行时已提速。

目标仍为用户要求的整体 F64 大幅提升区间。仅作条件预算：若全部 GEMV 都获得 1.15～1.19×，并且 D1 约 95.78% 占比及其他耗时不变，整体倍率约 1.143～1.181×。这是显式假设下的 Amdahl 换算，不是 decode 预测；它说明本批增益即使完整传递，也不足以宣称整体约 +66% 达标。历史 9.39→18.9 tok/s 没有因此获得新的因果归属。
