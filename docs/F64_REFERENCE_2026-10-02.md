# MICIUS F64 阶段收尾与源码覆盖说明

日期：2026-10-02。范围：当前 F64 数值契约、Q8 权重存储、bitwise correctness。

本轮完成 CF7 的定点代码与数据流排查，将已验收的基础路径整理回 `MICIUS/` 工程结构。CF5 已通过本轮正确性验收，但未通过端到端性能筛选，不进入本包的正式数值路径。本包没有新增性能优化，也不宣称达到 F64 性能上限。

## 交付内容与合入依据

运行时采用 `MICIUS-F64-D1 / PW2 NONE / D1 OFF` 的可信源码：48 个 CMake、源码、头文件、测试与 LICENSE 输入逐字节复用，与 CF7 冻结的 BASE 来源一致。相对最初的 `04-MICIUS.zip`，35 个输入相同、6 个修改、7 个新增；逐文件散列和差异在 `f64-closeout-evidence/runtime-changes.json` 与 `runtime-vs-original.patch`。

最初上传的源码已经包含 r1 准备输入和此前主要算术优化。此次新增的工程价值是：统一可复现的构建配置、保留完整 logits 对照及装载统计入口、保留已验证的默认关闭 D1 诊断、明确实验结论与来源。没有把历史收益再次计为本轮收益。

| 项目 | 本包选择 |
| --- | --- |
| GEMV | Q8_32 + AVX2 双行消费 + F64 累加 |
| 输入 | 调用期 F64 快照；FFN gate/up 共用一次快照 |
| scale | 私有 V1 绑定边界预验证；保留 checked fallback |
| attention | 有序 AVX2 V 聚合、time-quad score |
| FP | strict；参考 GEMV `fp-contract=off`；保留 frozen oracle |
| PW2 权重展开 | `NONE`；无展开权重 payload |
| D1 / ITT | 默认关闭；诊断能力保留 |
| CF5 | 实验归档保留在原 CF7 包；本包不含 CF5 源码或编译入口 |
| 公共 C ABI | `include/micius_runtime.h` 与原包一致 |

PW2 的既有源码依赖随可信 D1 源码完整保留，配置为 `NONE`；这不是对 PW2 性能候选的批准。这样可以复用已验收运行时输入，避免为了删实验依赖而再次改动引擎。

原 `CMakeLists.txt` 的默认选项接口保留。要启用上表配置，使用新增的 `f64-reference-windows` preset 或下方构建脚本。直接沿用旧 CMake 缓存不能代表这份配置。

## CF7 排查结论

完整机器码和数据流说明见 [F64_CF7_CLOSEOUT_2026-10-02.md](F64_CF7_CLOSEOUT_2026-10-02.md)。结论如下：

| 验收项 | 结果与处置 |
| --- | --- |
| CF7 目标身份与源码对应 | 既有结果已核对：Windows 11 / i7-1370P / CPU 4 / Clang 22.1.8；55 个源码输入、EXE/PDB、日志清单对应 |
| 正确性、准备、生命周期、尾部、回退 | 复用已完成的 CF7 三配置 CTest、32 步真实模型全 logits 对照、128 步输出检查，以及 Linux 边界与生命周期检查 |
| CF5 代码生成 | 解码与累加结构保留；运行时循环 115 条、611 B，微基准 114 条、587 B；均为 4 次循环栈访问 |
| BASE 是否退化 | CF7 两配置中的 Q8 主循环与已验收 D1 BASE 逐字节相同 |
| 端到端性能 | CF5 六配对仅 1 次获胜，中位配对收益 −0.5465%；不批准性能合入 |
| 准备与容量 | CF5 额外 1,096,581,764 B，准备中位约 0.717743 s；无可确认的正向 decode 摊销 |
| 未隔离因素 | 调用边界、实际缓存/带宽、后两轮频率或温度影响仍未分别量化；记录为未知，不阻塞已验收 BASE 的交付 |

CF7 BASE/CF5 中位吞吐分别为 18.874862 / 18.7785235 tok/s。这是已回传固定协议的记录，不是本包在新目录重新构建后的性能承诺。六配对结果也不足以证明 CF5 固有地稳定慢 0.55%。

“排查完成”表示这些项目已有明确处置，包括性能筛选失败后不合入；不表示每个实验都获得了正向结果。F64 局部极限、历史约两倍吞吐变化的因果归属仍未被证明，真实 tok/s 不设完成态数值预测。

## 覆盖、构建和使用

先备份当前源码，再覆盖。不要把旧 `build/` 缓存混入新构建。以下命令在原 MICIUS 的 Windows Bash 中使用，默认工程位置为 `C:\Projects\MICIUS`。

覆盖前备份源码及当前配置（不包含模型或历史二进制）：

```bash
cd /c/Projects/MICIUS &&
backup_items=(CMakeLists.txt src include tests docs scripts README.md LICENSE MICIUS.code-workspace) &&
if [ -f CMakePresets.json ]; then backup_items+=(CMakePresets.json); fi &&
tar -czf "/c/Projects/MICIUS-source-before-F64-$(date +%Y%m%d-%H%M%S).tar.gz" "${backup_items[@]}"
```

将 ZIP 解压覆盖到 **`C:\Projects`**。ZIP 自带 `MICIUS/` 根目录；最终应得到 `C:\Projects\MICIUS\scripts\build-f64-reference-windows.sh`。

然后执行绝对路径命令：

```bash
bash /c/Projects/MICIUS/scripts/build-f64-reference-windows.sh
```

需要 Python、CMake ≥ 3.21、Ninja 和 Windows x64 Clang64 工具链。历史目标验收使用 Clang 22.1.8（commit `6e4e79c2f86eeb534e324e583f2057dc9fd5ecab`）。其他编译器版本生成的机器码和性能不继承该数值结论。

脚本先检查 48 个运行时输入和源码目录内的遗留实验文件，然后创建 `build-f64-reference`，构建 CLI/sandbox 并运行全部 CTest。源码检查失败时保留本地内容，输出不一致路径；应先核对这些路径。已存在同名构建目录时，先将其改名保存，再运行脚本。日志写入独立的 `logs/f64-reference-build.*`。

新 CLI 的完整路径是：

```text
C:\Projects\MICIUS\build-f64-reference\bin\micius_cli.exe
```

如需在本机做一次已有协议的运行确认，可执行：

```bash
/c/Projects/MICIUS/build-f64-reference/bin/micius_cli.exe \
  --model-benchmark \
  --model C:/Projects/MICIUS/models/smollm2-360m-instruct-q8_0.gguf \
  --warmup 8 --steps 128 --cpu 4 --token 1
```

对已验收的同一模型，期望 `status=PASS`、`final_token=30`、`token_checksum=0x4f9cb9a464361ddf`、`last_logits_checksum=0x796b3ffb22c87b08`。该命令不是新一轮性能实验要求。

本包包含小型合成模型 `tests/fixtures/f64-smoke.gguf` 以复现本地正确性检查，不能用它报告真实模型性能。完整模型 SHA-256 为 `48ab3034d0dd401fbc721eb1df3217902fee7dab9078992d66431f09b7750201`；32 步固定 token=1 全 logits trace 的历史目标 SHA-256 为 `989d9ae57cd981b4596de0efda52c3d789c9eaef7448be761e7e999daf6114a7`。

## 回退

恢复覆盖前的源码备份，并将本包新增的文件移出源码树。不能仅用旧文件覆盖，因为 CMake 的源码 glob 仍会纳入新增 `.cpp`。相对最初上传的源码，本包新增运行时文件为：

- `include/AI/DecodeProfile.h`
- `include/AI/PreparedGEMVWeights.h`
- `src/AI/PreparedGEMVWeights.cpp`
- `src/AI/ReferenceF32WeightGEMVAVX2.cpp`
- `tests/decode_profile_tests.cpp`
- `tests/d1_runtime_contract_tests.cpp`
- `tests/prepared_weight_tests.cpp`

新增交付配置还包括 `CMakePresets.json`、两个 `*-f64-reference*` 脚本、本收尾文档/证据和合成 fixture。若覆盖前已存在同名文件，应恢复自己的备份版本。保留 `models/`、历史 EXE/PDB 和历史测量，使用新的空构建目录重建回退版本。

## 验证边界

本轮使用 Linux/GCC 做一次交付整合检查；Windows 真实模型正确性与性能来自此前已核对的目标机证据。运行时 48 个输入保持可信基线原字节，当前 Linux 主机没有被当作用户的 Windows 性能环境。详细本轮结果在 `f64-closeout-evidence/local-validation-summary.json` 与 `local-ctest.txt`。

本轮结果：11/11 CTest 通过；合成模型 32 步全 logits 与既有基线逐字节一致；128 步 token/logits 校验一致。CLI 和 sandbox 构建成功，源码检查在构建前后均通过。GCC 本地整合检查关闭了 LTO、LLD 与静态运行库；Windows preset 保持已验收配置对应的开启状态。

既有 CF7 ASan/UBSan 检查通过；LeakSanitizer 曾因宿主 `/proc` 条件不可用而明确关闭，不能声称泄漏检查已通过。本轮不重复展开这些已完成检查，也不以交付收尾替代未来新候选所需的验收。
