# CF7 定点排查：运行时、微基准与完整消费成本

本次只回答 CF5 微基准收益为何不能直接成为当前运行时收益，以及是否存在应阻止基础源码交付的未处理问题。未生成新性能候选、未重跑目标机性能采样。

## 可核对的机器码

从用户回传 CF7 ZIP 提取 BASE/CF5 的 EXE、PDB 和 disassembly；PDB GUID/age 与 EXE CodeView 一致，选定函数边界内每条指令的字节均与 EXE 对应。验证字节数：BASE 9,653 B、CF5 12,399 B。来源身份见 `f64-closeout-evidence/input-identities.json` 与 `exe-pdb-identities.json`。

以下以每轮处理两行各 32 个权重（共 64 weights）的内层循环为单位：

| 静态项目 | CF7 BASE 预验证 Q8 | CF6 微基准 CF5 | CF7 运行时 CF5 |
| --- | ---: | ---: | ---: |
| 指令数 | 98 | 114 | 115 |
| 机器码字节 | 486 | 587 | 611 |
| 循环内栈访问指令 | 0 | 4 | 4 |
| 显式内存操作数宽度合计 | 328 B | 706 B | 706 B |
| 其中栈操作数宽度 | 0 B | 128 B | 128 B |
| F64 向量乘法 / 加法 | 32 / 16 | 0 / 0 | 0 / 0 |
| F64 FMA | 0 | 16 | 16 |
| shuffle / permute / integer add | 0 / 0 / 0 | 16 / 16 / 16 | 16 / 16 / 16 |
| 内循环 CALL | 0 | 0 | 0 |

内存操作数宽度是静态指令统计，包含重叠加载和栈读写；不是独立数据字节、cache miss、DRAM 流量或周期测量。指令数也不是性能比值。

运行时 CF5 相比微基准多一个寄存器清零；索引寻址、循环控制及寄存器分配不同。仍保留 16 次 FMA、两行的八条累加链、同样的解码结构、两个表加载和四次栈访问。没有发现“集成后换成了昂贵的逐权重通用解码”之类的失配。不能据此证明这些细小代码生成差异毫无性能影响。

CF7 BASE/CF5 内保留的 Q8 checked 与 prevalidated 两种主循环，分别与已验收 D1 BASE 的机器码逐字节一致；预验证主循环无栈访问、CALL、FMA 或 EVEX。散列及具体汇编见 `loop-comparison.json` 和三个 `*-loop.asm`。

## 完整调用边界

CF5 的 `PairSums` 在目标 Clang 构建中成为独立函数。实际完整块路径每输出两行调用一次，写出两项 double，再由外层检查有限性/范围并转换为 float。它包含 Windows ABI 的寄存器保存/恢复。外层还执行矩阵尺寸、FP 控制字、地址范围和重叠检查。

在本模型的 32 层与 LM head 下，依据实际矩阵形状，每 token 的行对数为：

```text
(32 × (1600 + 960 + 2560 + 2560 + 960) + 49152) / 2 = 162816
```

因此成功 CF5 路径每 token 有 162,816 次 `PairSums` 调用。BASE 在一次矩阵 GEMV 调用内直接遍历各行对，不经过这个 CF5 helper。微基准的 CF3、CF5、CF6A 和 F32 control 则均逐行对调用各自 kernel；CF5 对 CF3 的胜幅不能直接覆盖它相对运行时 BASE 的边界差异。

微基准 CF5 自身同样有一次行对函数调用，因此不能把运行时的全部 helper 开销都说成是“集成新增”。能确认的是比较双方不同，运行时还要承担完整 API 契约。没有隔离这些边界的目标机对照，不能给出其独立耗时占比，也没有证据承诺强制内联会使 CF5 获胜。

CF7 源码确认：bank 在绑定时准备，消费时没有再次分配/构建 bank；FFN gate/up 的 F64 输入快照仍然共享。bank 的原始权重指针、尺度指针、形状与调用矩阵对应；真实目标日志确认 161 个矩阵 ready，没有误落入预算回退。目标模型的列数都是 32 的倍数且行数为偶数，尾列与奇数尾行不是这次性能结果的解释。通用尾部和回退正确性已在此前专项检查覆盖。

## 数据流和比较对象

CF6 的 44/44 配对优势是 CF5 对实验 CF3。两者影子表示约 3.03 B/weight，说明该实验中的提升主要来自消费实现；它不是 CF5 对当前 Q8 BASE 的比较。

当前 BASE 的存储组成约为 1 B Q8 + 16/32 B descriptor，即约 1.5 B/weight。CF5 bank 为 194/64 B/weight，并且运行时保留 canonical Q8 和 descriptor。保留不等于每次消费都读取两套权重；不能据总占用直接声称 DRAM 流量翻倍。

CF6 按单一矩阵类别重复扫描，使用预先准备且不变的输入；实际解码按每层 QKV → attention → O → gate/up → down，再到 LM head，输入会变，所有层和其他状态交错消费。query 或 FFN 输入的共享不等于跨输出行权重转换可以同样共享。容量、访问顺序和完整调用边界都需要在真实运行时付费，单矩阵微基准不能代替它。

CF5 相对 F32 control 也有取舍：既有 CF6 测量在大工作集下高 12.08%～17.48%，较小工作集下低 24.51%～31.14%。CF6A 消除循环栈访问后的净收益有限，但它同时改变调度/寄存器分配，不能单独证明 spill 不重要。

## 验收与停止条件

既有 CF7 真实模型验证与性能数据仍是最终合入依据：三配置测试和 bitwise 对照通过；六配对 CF5 只有一次获胜，中位收益 −0.5465%，额外 payload 1,096,581,764 B，准备中位 0.717743 s。正确性通过使候选可继续研究，不使它自动成为可启用的性能成果。

本次排查没有找到必须修复才可交付 BASE 的问题。各项按证据关闭：可信 BASE 固化交付，CF5 保留为未通过性能筛选的实验，代码生成/调用/工作集的具体观察归档。缓存、温度/频率、各边界独立耗时和历史吞吐约两倍变化的因果归属继续标注未知。

这允许结束当前收尾工作，而不把“所有机制均已排除”或“达到 F64 局部极限”写成结论。若未来重启 CF5，逐行对调用边界是一个具体可检验问题；本轮不为验证它再生成变体或追加采样。
