## Reference 重建

2026-08-24 起的 v0.6 重建首先建立可验证的单线程 reference 路径。此前草稿的问题涉及逐层 KV、Q/K 行顺序、每 32 权重的 scale、ABI 尺寸检查、模型生命周期及 CLI 输出语义；不能用旧框架中的 speculative、worker 或池化代码存在来证明这些能力已经可用。

重建建立了逐层 KV、真实 token prefill/decode、reset、logits 读取和明确错误状态，使用具有形状、类型、字节长度的 V1 绑定接口。缺乏尺寸信息的旧权重绑定入口保留符号并拒绝执行。CLI 去除了将占位分词或虚构文本当作模型生成的路径。

第二轮修复了 GGUF Q/K 重复排列、Q8_0 scale 粒度、V1 entry_size 步进、失败重绑定的回退、首个输出 token 丢失及错误状态处理，并加强独立 oracle。此时文档中的“真实模型 parity 待验收”是阶段状态；后续真实模型证据不能倒填为当时已完成，也不能被这条旧状态否定。

来源：[重建计划](REMEDIATION_PLAN.md)、[首次验证](VERIFICATION_RESULTS.md)、[第二轮验证](SECOND_ITERATION_VERIFICATION.md)。

## Q8_32 与 attention 实现整理

| 阶段 | 工作与得到的结论 | 当前处置 |
| --- | --- | --- |
| checked AVX2 GEMV | 在明确边界检查和原参考顺序下向量化 Q8_32 消费 | 保留为基础与回退路径 |
| r3/r4 scale 预验证 | 把可信模型 scale 验证前移到私有 V1 绑定边界；修正 Windows 测试头文件路径 | 当前 preset 启用；不宣称早期小收益已经普遍成立 |
| r5/r6 双行 GEMV | 两个输出行共享输入转换；直接短权重加载减轻寄存器压力 | 当前启用；严格 AVX2 检查与可用更多寄存器的 GCC native 结果分开记录 |
| attention value | 保持每个结果的累加顺序，实现 AVX2 聚合 | 当前启用 |
| r7 query F64 cache | 在 key 扫描前缓存 query；微基准收益没有等比例传递到目标运行时 | 当前关闭 |
| r8 time-quad score | 四个时间行共享 query 转换，保留各行维度顺序和时间归约顺序；余数走原路径 | 当前启用 |
| r9 compact scales | 将私有每块 descriptor 改为紧凑 float；正确性可行，但当轮运行时收益有限 | 当前关闭 |
| r1 F64 cleanup | 调用期准备 F64 输入，跨输出行复用；FFN gate/up 共用输入；约束参考 GEMV 浮点收缩 | 当前启用 |

r7 与 r8 利用的是 query/输入在同一消费中的实际复用。不同输出行具有不同权重，不能据此推断权重转换也能同样共享。

r1 历史固定协议的 strict 对照中，普通中位吞吐约从 9.151619 到 9.403544 tok/s，中位配对收益约 +2.0984%，5 对中 4 对获胜。这是当时的配对结果；当前约 19 tok/s 的记录属于后续批次，不能把跨批次数值比直接解释为 r1 或某个候选的收益。

设计细节保留在 [文档索引](README.md) 所列各后端文件中。
