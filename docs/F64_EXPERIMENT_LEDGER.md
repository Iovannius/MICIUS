# F64 实验台账

整理日期：2026-10-03。核心约束是当前数值契约、Q8 主存储与 bitwise correctness；实验可增加 exact 影子表示，但容量、准备和完整消费成本必须一起计入。

“通过正确性”“通过目标微基准筛选”和“通过端到端性能验收”是不同状态。当前正式 reference 选择见 [当前状态](CURRENT_STATUS.md)，原报告入口见 [历史索引](history/README.md)。

## 基线与表示路线

| 阶段 | 比较对象与证据 | 结果及处置 |
| --- | --- | --- |
| RB1 | 对齐同一消费与数值契约后的旧 Q8 A 与 r1 Q8 core；目标合成矩阵 | 各配置变化约 −0.24%～+1.60%，未显示明显额外实现损失；不是完整模型测量 |
| RB1 的 B | 原始 Q8 整数展开为 exact F64，8 B/weight；尚未预乘 scale | 小工作集可受益，较大权重工作集不利；不能据此采用全面展开 |
| PW1 | 真实运行时 NONE 对 QKV/O 原始 F64 权重快照 | 配对中位约 −11.36% / −7.16%，均 0/6 胜；额外 375 / 225 MiB；不采用 |
| A1 | 独立单矩阵与 32 矩阵轮转访问 | F64 展开在 QKV/O 轮转时明显转负；支持工作集影响，不单独证明唯一缓存机制 |
| PW2 | 真实运行时 NONE 对原始 F32 权重快照 | 配对中位 −3.4011% / −2.2120%，均 0/6 胜；额外 187.5 / 112.5 MiB；保持 NONE |
| A2 | 与 PW2 目标热循环对应的 F32/Q8 访问实验 | QKV/O 单矩阵约 +33.87% / +34.05%，轮转约 −24.99% / −24.28%；仍有容量与访问取舍 |

PW1/PW2 的快照是原始权重值表示，不能与 E2 的预缩放 exact F32 权重混为一谈。PW2 的准备确已成功，32 个矩阵进入准备状态；其目标 Clang 热循环无 spill，不能用另一套 GCC 的 spill 来解释目标机退化。

## 定位与算术消费实验

| 阶段 | 主要证据 | 可以得出的结论 |
| --- | --- | --- |
| D1 | GEMV 占所测分类时间约 95.7772%，输入准备约 0.1246%；FFN 约 62.5708%，FFN+LM 约 74.9967% | 优先研究 GEMV，尤其 FFN/LM；尚未单独解释其慢的微观机制 |
| E1 | 条件化 exact FMA 独立消费体，相应大工作集组约 +14.87%～+17.04% | F64 计算域仍有局部优化空间；不是当前运行时的端到端收益 |
| S1 | 针对 E1 的循环 spill 去除 | 没有跨形状稳定净收益；不推广 |
| S2 | 达到无循环栈访问等代码目标 | 仍没有足够一致的性能收益；不推广 |
| OBS1/F1 | 修正内联归属后的目标 profiling | 支持继续关注资源压力；不同分母的指标不可直接相加，尚未证明唯一端口瓶颈 |
| E2 | exact 预缩放 F32 权重消费，对照 E1；影子约 4 B/weight | 单矩阵约 +62%～+88%，但 QKV/O/FFN 轮转约 −12%～−22%，LM 约 −19.51%；不集成 |

E2 的 44 个配对为 24 胜、20 负。它说明减少转换和算术可带来较大局部收益，也说明工作集增长会吞噬该收益；不能把 E1、E2 的相对比例连乘成当前模型 tok/s。

D1 只能定位时间。转换、算术与表示容量的解释需要结合 B、E1/E2、访问实验和机器码。准备占比小只限制“直接删掉这段准备”的收益，不能排除增加少量可摊销准备、显著减小后续消费成本的路线。

## 紧凑 exact 表示

| 阶段 | 已有证据 | 处置与边界 |
| --- | --- | --- |
| CF1-R1 | 恢复后的紧凑表示候选与校验记录 | 未形成综合性能优势；恢复包具有新身份，不冒充原始遗失归档 |
| CF2 | D24-F32/direct64，影子约 3.03125 B/weight；表示、累加链与浮点环境校验 | exact 可行；本地 GCC 指令与正确性记录不等于目标 Windows 性能 |
| CF3 | planar 194 B/双行块布局，共享查表；本地循环进一步收缩 | 后来成为 CF6 目标微基准对照；不是当前运行时 BASE |
| CF4 | J21/J22 联合编码，J22 块从 194 B 到 178 B | 90 条已生成 CF3 GCC 指令对 106 条手工配方，仅用于筛选；不能推出目标 Clang 慢多少 |
| CF5 / CF6 | 目标微基准、完整消费成本与表示正确性 | 通过候选集成筛选，进入独立运行时分支验收 |
| CF6A | 去掉循环栈访问的变体 | 约 −0.84%～+1.98% 净变化；寄存器分配和调度也变化，未单独隔离 spill |
| CF7 | 真实运行时 BASE、CF5、FALLBACK 的正确性与 BASE/CF5 配对测量 | 正确性通过，性能未通过；CF5 不合入 |

CF5 对 CF3 在 44/44 配对中获胜：单矩阵约 +32%～+35%，大工作集约 +6%～+10%，LM head 约 +6.5%。两者影子容量都约 3.03 B/weight，改善主要来自消费实现，不能归因于表示规模缩小。

CF5 对 F32 消费对照则有取舍：大工作集吞吐高 12.08%～17.48%，小工作集低 24.51%～31.14%。实际访问顺序、复用和使用范围决定集成价值，不能概括成普遍降低消费成本。

CF7 的对照是运行时 Q8 BASE，CF6 的对照之一是实验 CF3，二者不能互换。影子约 3.03 B/weight 也不是整个进程的权重总容量：CF5 仍保留 canonical 数据，BASE 的 Q8 加 descriptor 存储口径也不同。

已完成收尾确认：CF7 BASE 热循环与 D1 可信 BASE 对应；CF5 运行时循环为 115 条/611 B，微基准为 114 条/587 B，两者均有 4 次循环栈访问。PairSums 的调用边界确实存在，但 CF3/CF5 微基准也具有逐行对调用，不能把所有调用开销都算成运行时集成新引入的损失。

调用、缓存/带宽、后两轮热状态尚未独立量化。这些未知不能自动变成“再内联即可获益”的结论，也不阻止本轮按结果拒绝 CF5 合入。详细证据见 [CF6 评审](f64-closeout-evidence/CF6-target-review.md)、[CF7 评审](f64-closeout-evidence/CF7-target-review.md) 与 [CF7 收尾](F64_CF7_CLOSEOUT_2026-10-02.md)。

## 保留的工程判断

优先利用实际存在的共享和复用，避免为减算术制造更大的长期工作集。位恢复与 F64 交织的筛选必须计入零值、常量供给、加载和全部累加链，而非只数核心公式。

目前没有证据把主要损失指向分配器。布局可能改变访问成本，需要具体数据流证据；恢复旧内存池本身不是性能结论。

现有实验展示了约束之间的困难取舍，但尚未穷尽实现空间，不能证明“已到局部极限”。历史约两倍吞吐差异也没有完成因果分解。当前不提供 22–30 tok/s 完成态预测，不用后续 INT8/VNNI 设想替代本阶段证据。
